# 柱规格 · Pixel 8 真桌面（对表 X64 · 触控优先）

> **状态**：**规格草案**（未点名、未占 ★）。USB 键柱已收 → [`手机USB键盘.md`](手机USB键盘.md) / [`项目/进展/路线图1108.md`](../项目/进展/路线图1108.md)。  
> **标杆用法**：X64 = **能力面/基础设施**参照（存盘、FB 门面、热更、稳定性）→ [`三架构进度.md`](../三架构进度.md)；**不是**把 NUC 桌面 UI 原样塞进手机。  
> **交互口径**：**触摸 > 键鼠**；手机壳要重做布局与手势，勿假设「插键鼠才是桌面」。  
> **板包**：`Kernel/HAL/Arm64/Board/pixel-8/`。主攻 Pixel；MIX 仅对照。  
> **产品名**：Blocks。点名后再开刀。

## 1. 目标（一句话）

在 **Pixel 8** 上做出 **可触控的手机向 Blocks 壳**：能存盘、能全屏交互、能热更——底层能力向 X64 看齐，**界面与输入模型按手机另做**。

| 维度 | 已有（1108） | 本柱要到 |
|---|---|---|
| 输出 | ABL splash 彩条 + 字；Cereal | **手机向全屏 UI**（大控件/竖屏；非 NUC 任务栏+光标桌面） |
| 输入 | USB 坞键盘（排障/bringup ✅） | **触摸为主**；USB 键为辅（调试/无触摸时）；鼠非主路径 |
| 存储 | 无 | **可挂载根/系统卷** |
| 加载 | `fastboot boot` | 仍优先；持久启动另柱 |
| 网 / 热更 | 无；靠电脑 `fastboot boot` | **存盘后尽早**：坞 **有线网口** + HotSend 落核（少反复刷机）；Wi‑Fi 仍候补 |

---

## 2. 屏幕能不能直接对标 X64 桌面？

**不能当「同一套桌面换个分辨率」。**

| 可对标（底层） | 不对标（产品/UI） |
|---|---|
| 帧缓冲格式、stride、Present/上滚门面 | 任务栏、多窗、鼠标指针、悬停 |
| Fat/VFS、HotSend、键鼠 HID 协议栈 | 「键鼠最优先」的课桌假设 |
| 稳定启动、日志、错误语义 | 横屏窗口管理、右键菜单为主 |

X64 桌面是 **键鼠+多窗** 课桌隐喻；手机是 **手指+单层/全屏栈**。Pixel 已有 splash 像素能力，只说明 **能画**，不说明 **能原样跑 Gui Desktop**。

**结论**：C 柱做「手机壳」；共用画点/合成 primitive 可以，**Desktop/Taskbar/Cursor 路径默认不搬或只作调试旁路**。

1. 全屏 **可点** 壳；  
2. **触摸**走通主路径；  
3. Cereal 日志完整。  
USB 键盘 **不**作壳 MVP 必达（排障加分）。

### 柱 B · 持久存储

#### B 答疑：单独分区？能从真分区启动吗？

| 问题 | 口径 |
|---|---|
| **存盘是单独分区吗？** | **应当是**。GPT/GUID 上划 **Blocks 自有区**（或复用可牺牲的 userdata 子卷，须书面锁定），只在该区建 FAT/现网 FS。**禁止**当工作盘去写 `system` / `vendor` / `super` 安卓槽。 |
| **能从手机真分区启动吗？** | **能，但是后话（柱 G）**。日常仍 **`fastboot boot` 把核打进 RAM**；热更只更新 **Blocks 区里的镜像**，再起可以是：① 仍 fastboot boot 新 img；② 或自研小 stub 从 Blocks 区加载（仍不换 ABL）；③ 最后才考虑 `flash boot`/`vendor_boot` 进真槽。③ = 砖机风险最高，**另立项**，不进中期绿。 |
| **热更「再起」中期指什么？** | 优先：**有线热更写好 Blocks 区** + 文档化的再拉起方式（可仍是一次 fastboot boot 本地已打好的 img，或板内 loader）。目标是少「整包重打包+跨机拷」，不是一上来取代 ABL。 |
| **分区是 FAT32 吗？** | **中期推荐是**：Blocks 自有区格式化成 **FAT32**（对表 X64 `BLOCKS:` / 现网 Fat 栈 / HotSend）。不是安卓 `ext4`/`f2fs` userdata。以后若要更大文件再议 exFAT，不挡中期。 |

#### 单独分区后的启动链（三档）

```
上电 → ABL（谷歌）→ ?
```

| 档 | 链 | 谁从哪加载 Kernel | Blocks 分区角色 | 何时用 |
|---|---|---|---|---|
| **① 现网 / 中期默认** | ABL ← `fastboot boot boot.img`（RAM） | **电脑推 img 进内存**；ABL 不读 Blocks 区 | **只当数据盘**：落 `Kernel.elf`/资源；HotSend 写这里 | B+N+E 主验收 |
| **② 少电脑（目标增强）** | ABL ← 仍临时 boot **小 stub**（或一次 flash 极小 loader）→ stub **读 Blocks 区 FAT** → 跳进新核 | stub / 二级加载器 | 镜像仓库 + 可选 `ROOT.CFG` | E 深化；仍尽量不换安卓 boot 槽 |
| **③ 真分区自起（柱 G）** | ABL ← 槽内 `boot`/`vendor_boot`（已 flash Blocks）→ 可再读 Blocks 区 | ABL 直接或经我们改过的 boot | 同 ②，且启动路径依赖槽 | **另立项**；砖机面最大 |

要点：

- **建 FAT 分区 ≠ 自动从该分区开机。** ABL 默认只认自己的 boot 槽，不认我们新划的 GPT 名。  
- 中期「热更后再起」常见实操：HotSend 更新分区里的 elf **同时**主机侧已有可 `fastboot boot` 的 img；或 ② 用 stub 只读分区。  
- 分区建议：**独立 GPT 项**（名如 `blocks`）+ **FAT32** + 卷标可对表 `BLOCKS`；容量按核+资源预留（数百 MB～数 GB 量级，点名时定）。

#### UFS 难点在哪？（B0 卡点）

> 协议栈是标准 **UFSHCI + SCSI**；难在 **Tensor 上电/PHY/厂商 CAL**，不是「不会读扇区 API」。

| 层 | 难点 |
|---|---|
| **电源/复位** | ABL 交权时 UFS 常 **断电**；须按序拉 VCC、复位脚、refclk（错序 = 永远 NOP） |
| **时钟/隔离** | `GATE_UFS_*`、UniPro mclk、PMU PHY isolation；无 Linux 时钟框架时要 **MMIO/固定频率** 证据 |
| **PHY + CAL** | 三星/谷歌 `ufs-cal` 表（HS-G4 等）；裸机常要移植或最小子集，**禁止瞎改 PMA** |
| **Host 初始化** | UFSHCI 链路启动（NOP OUT → Device Init → …）超时难排；须对照 JEDEC + 现网 dmesg |
| **多 LUN / 分区** | `sda/sdb/…` 多 LUN；认错 LUN 易碰到 boot/超级分区 → **只读枚举先于任何写** |
| **IOMMU/一致性** | `dma-coherent` / sysreg IOCC；描述符地址不对 = 静默失败 |

社区旁证（Pixel 8 系 / zuma）：UFS HCI 一带约 `0x13200000`，PHY `0x13204000` 量级——**开刀前用本机 DT/`sysfs`/拆包核复核**，勿抄死地址当唯一真理。

#### UFS 准备工作（开 B0 前）

| # | 准备 | 产出 |
|---|---|---|
| 1 | 本机（或同系列）安卓下：`/sys/firmware/devicetree` 或 `dtc` 抽出 **ufs / ufs-phy / regulator / pinctrl** | 基址、中断、时钟名、复位脚表 |
| 2 | `dmesg` 抓一次成功链路：速率、mclk、LUN 名 | 对照「绿长什么样」 |
| 3 | 拉一份 AOSP/`gs` 树里 **zuma ufs-cal**（只读） | CAL 表来源；许可注意 |
| 4 | 精读 **JEDEC UFSHCI** 初始化状态机（标准优先） | 板码只准填 SoC 差异 |
| 5 | 分区地图：`ls -l /dev/block/by-name` + `sgdisk`/`parted` 只读 | 选定 Blocks 自有区候选；**写白名单** |
| 6 | 救砖路径书面化：仍可 `fastboot boot`；不写 boot 槽 | E2/G 边界 |
| 7 | Cereal 日志宏：电源步、HCI 状态、UIC 错误码 | 真机一次一步可复盘 |
| 8 | （可选）先在 QEMU/文档环境跑通 **UFSHCI 状态机空转**，再上板碰 PHY | 减「软硬一起糊」 |

### 坞口总表（现网 Type-C hub · 能否「都能用」）

> **不能默认全开。** 坞内部是 **USB hub + PD +（可能）DP Alt-Mode + USB 网卡 + USB 读卡**；路径不同，难度差一个数量级。

| 口 | 协议实质 | 本柱态度 | 说明 |
|---|---|---|---|
| **充电 Type-C** | PD/供电 | ✅ 必用 | 墙充；Host 稳枚举前提 |
| **USB-A** | USB HID/MSC/… | ✅ 主下游 | 键已绿；MSC/网卡若挂在 A 树同形 |
| **USB-C 数据** | 仍是 hub 下游 USB | 🔧 可做 | 与 A 口同属 USB；验收可后补「C 口键/盘」 |
| **RJ45** | 几乎总是 **USB 网卡**（非板载 PCI） | ✅ **中期必做（柱 N）** | 热更主路；须认 VID/PID 驱动 |
| **读卡器** | USB **MSC**（或 UAS） | 🔧 可做·次优先 | 对表现网 MSC；**不能替代 UFS 根**（可作搬运/备份卷） |
| **HDMI** | 多是 **DP Alt-Mode → HDMI 转换**，不是「USB 显卡」 | ⛔ 远期·很难 | 要手机侧 **DisplayPort Alt-Mode + 绑定**，与刷 splash/DECON 不是一条路；勿指望插上就镜像 Blocks 屏 |

**一句话**：USB 树上下游（A/C/网/读卡）有望逐个点亮；**HDMI ≠ 再枚举一个 USB 设备**，单独一座山。

## 7. 推荐推进序

```
A0 观测
  → B 存储
  → N 坞有线 ──► E 热更     ← 尽早减刷机
  → C 显示底座
  → U0 规格 → U1 壳
  → T 触摸接真
       │
       └─ D 键辅路（随时可插）
```

**卡点**：B（UFS）仍最大；其后 **N**（坞网是否 USB-NCM/Realtek/… 要认驱动）可能第二卡。  
**UI/触摸**不堵热更：先 N+E，再 C/U/T。

## 8. 刻意不做（本阶段）

| 项 | 原因 |
|---|---|
| 把 X64 Desktop/任务栏/光标原样移植 | 手机隐喻不同；你也未打算键鼠当主力 |
| 触摸未绿前强绑 USB 鼠 | 本末倒置 |
| 相机/蜂窝/听筒 | 非壳主路径 |
| 空 stub 冒充 Gui Desktop | 禁止半截门面 |
| MIX 并行真桌面 | 对照即可 |
| 未认芯片就开「全坞功能」 | 网/卡/HDMI 路径不同；HDMI 尤禁碰运气 |
