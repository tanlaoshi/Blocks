# Blocks 集成开发环境

> **状态**：规格。还没改代码。  
> **决定**：产品外壳用 **VSCodium**（Code-OSS 的可再发行构建）。Blocks 仓里只放扩展、启动器和产品补丁，不放编辑器源码树。  
> **排期**：本柱独立。不替换活档 ★（现为 `psmp-3b`）。要排进日档须另说。  
> **宿主**：Debian / Ubuntu x64。Pi、Duo、QEMU 是**目标**，不是装 IDE 的机器。

相关入口：[`env.sh`](../../env.sh)、[`Bingo/BINGO.md`](../../Bingo/BINGO.md)、[`Bingo/App/`](../../Bingo/App/README.md)、[`Tools/Scripts/gen-compile-commands.sh`](../../Tools/Scripts/gen-compile-commands.sh)。热传是独立仓 `~/HotSend`，见协作口令「核传」。

## 1. 产品是什么

学生和贡献者打开 **Blocks IDE** 这一个窗口，做完现在要在编辑器旁边再开终端才能做的事。第一件是串口：看见 `blocks>`、在里面打命令，都发生在 IDE 里，不必再留一个 `picocom` 或「专门跑 QEMU 的终端」。

同时仍要能：

1. 认到仓库根（含 `env.sh`、`Boot/`、`Kernel/`、`Runtime/`）。
2. 按架构和板编内核。
3. 从 `Bingo/App/Template` 起一个应用，`make` 出 ELF。
4. 内核 C 代码能跳转（走现成的 `compile_commands.json` + clangd）。

窗口标题、数据目录、桌面图标是 **Blocks IDE**。编辑、搜索、终端、扩展市场用 VSCodium，不自研。

编、跑、刷卡、热传、串口会话仍调用仓库和 HotSend 里的脚本。IDE 不另写一套工具链，不把 `build` / `run` 的逻辑复制进 TypeScript，也不在 TypeScript 里读串口字节。QEMU 的显示器仍是系统里的 QEMU 窗口；收进 IDE 的是串口会话，不是画面。

## 2. 三块构成

| 块 | 职责 | 跑在哪 |
| --- | --- | --- |
| **扩展** | 命令、架构/板、新建应用、终端任务 | 进程内，随 IDE 加载 |
| **启动器** | 找到 VSCodium，带上 Blocks 的数据目录和扩展 | `blocks-ide` 壳脚本 |
| **产品补丁** | 标题、应用名、数据目录、关掉自动更新、桌面项 | 解压后的那份 VSCodium 上的 `product.json`，外加 `.desktop` |

开发扩展时用系统已安装的 `codium` 即可。打出「打开就是 Blocks IDE」的成品时，再解压一份钉死版本的官方 linux-x64 压缩包，只改其中的 `product.json` 和图标。不编译 Electron，不把 `microsoft/vscode` 或 `VSCodium/vscodium` 的源码引进本仓。

系统里那份 `codium` 不动。补丁只打在 Blocks 自己解压的副本上。

## 3. 已有能力（IDE 只包一层）

`source ~/Blocks/env.sh` 之后的短名，本柱直接调用：

| 短名 | IDE 里的用途 |
| --- | --- |
| `build` | 编内核。参数与终端相同：`build`、`build arm64`、`build arm64 pi`、`build riscv duo`、`build arm64 BOARD=rpi-3b` |
| `boot` | 编 `BOOTX64.EFI` |
| `run` / `run --headless` | x64 QEMU。`Runtime/run.sh` 始终 `-serial stdio`：`blocks>` 就在启动它的那个终端里。`--headless` 只关掉 GTK 窗口 |
| `run-virt-arm` / `run-virt-riscv` | virt 目标。图形模式串口在 `mon:stdio`；`--headless` 为 `-nographic`。会话同样在启动它的终端 |
| `serial` | **待加的薄短名**（见第 4 节）。真板交互串口。今天仓库没有这条，只有热传/部署在用同一端口 |
| `smoke` | 无头冒烟 |
| `boards` | 列板包，供选择板时对照 |
| `Kernel/Tools/build-sdk.sh` | 打 `Kernel/Build/BlocksSDK` |
| `Bingo/App/Template` | 新建应用的毛坯 |
| `Tools/Scripts/gen-compile-commands.sh` | 生成 `Kernel/compile_commands.json`（已在根 `.gitignore`） |

刷卡与热传放在后面的刀里，同样只调用：

| 短名 | 用途 |
| --- | --- |
| `ck-pi-sd` | Pi：固件→bootfs，`Kernel.elf`→BLOCKS |
| `ck-duo-sd` | Duo：`Kernel.elf`→LABEL=BLOCKS。禁止对 Duo 调 `ck-pi-sd` |
| `deploy-duo` / `deploy-nuc-usb` | 免拔卡 / U 盘热更 |
| `~/HotSend` 的 `hotsend` | 核传。有线优先。不把 HotSend 拷进 Blocks |

调用方式固定为同一个 shell 里 source 再执行，这样函数短名才存在：

```bash
bash -c 'source "$BLOCKS_ROOT/env.sh" && build arm64 pi'
```

工作目录由 `env.sh` 里的函数自己 `cd`。IDE 把这段放进**集成终端**，不藏进只写 Output 的通道。失败时终端里就是脚本原文，和手敲一致。

终端按用途分开，互不抢标准输入：

| 终端名 | 谁占用 |
| --- | --- |
| Blocks 构建 | `build` / `boot` / `make` / 刷卡 / 热传 |
| Blocks 串口 | `run`、`run-virt-*`，或真板的 `serial`。这个终端被客户壳占住，不再拿来编译 |

## 4. 串口

串口是本柱要收进来的那一个窗口。分两条，扩展都只负责打开「Blocks 串口」终端并 source 后执行短名。

### 4.1 QEMU

x64 的 `run` / `run --headless` 把客户壳挂在本进程的标准输入输出上。virt 的图形模式是 `mon:stdio`，无窗口模式是 `-nographic`。所以「运行」就是在「Blocks 串口」里执行对应短名：人在这个终端里看到启动日志，就绪后直接打 `blocks>` 的命令。

选「运行（窗口）」时，GTK / ramfb 仍弹出系统里的 QEMU 窗口；串口不跟过去，留在 IDE 这个终端。选「运行（串口）」时加 `--headless`，没有那块画面。

这块板是 `rpi-3b` 或 `milk-v-duo-s` 时，「运行」不启动 QEMU。真板的壳在 USB 串口上，走 4.2。

### 4.2 真板

Pi、Duo 的交互壳今天要另开一个串口程序，波特率 **115200**，设备与 `deploy-duo`、`deploy-nuc-usb` 相同：`${KSEND_PORT:-/dev/ttyUSB0}`。仓库还没有这条短名。开工时加：

- `Kernel/Scripts/run/serial.sh`：调用本机 `picocom`，波特率取 `KSEND_BAUD`（默认 115200），设备取 `KSEND_PORT`（默认 `/dev/ttyUSB0`）。
- `env.sh` 增加 `serial()`，转调该脚本。

IDE 设置 `blocks.serialPort` 非空时，先导出为 `KSEND_PORT` 再执行 `serial`。端口和波特率只写在这一处 shell 里。缺 `picocom` 时，脚本在终端写明要装的包名，扩展不去读 `/dev/ttyUSB*`。

同一设备节点不能两个进程一起打开。串口终端还开着时，热传和 `deploy-*` 会因端口被占而失败；先停掉「Blocks 串口」再热传。IDE 不替用户杀掉对方进程。

扩展标识：`blocks.blocks-ide`。命令标识前缀：`blocks.`。

## 6. 两种工作区

| 工作区 | 怎么认 | 主命令 |
| --- | --- | --- |
| **系统仓** | 文件夹内有 `env.sh`，且同时有 `Boot/`、`Kernel/`、`Runtime/` | 编内核、运行、冒烟、编开发包、生成编译数据库 |
| **应用目录** | 有 `Makefile`，且能解析到 `BLOCKS_SDK` 或用户刚从模板生成 | 编应用 |

找根的顺序：

1. 设置项 `blocks.root`（绝对路径）。
2. 从当前工作区向上找，直到命中「`env.sh` + 三个目录」。
3. 都没有：命令停住，终端说明要打开的是 `~/Blocks` 或去设置里填根。不猜测家目录。

应用毛坯今天的默认 SDK 路径是相对模板位置写的：

```make
BLOCKS_SDK ?= $(abspath ../../../Kernel/Build/BlocksSDK)
```

复制到 `~/MyApp` 之后，这个相对路径是错的。新建应用时，扩展把该行改成仓库内的绝对路径 `$BLOCKS_ROOT/Kernel/Build/BlocksSDK`。开发包目录还不存在时，先提示运行「编开发包」，不生成一个编不过的目录还假装成功。

内核不在打开应用目录时自动 `build`。两个动作分两个命令。

## 7. 命令与设置

命令面板用中文。底下仍是第 3 节的英文短名。

### 7.1 第一期命令

| 面板文字 | 行为 |
| --- | --- |
| Blocks: 编内核 | `build`，带上当前架构和板。x64 课机就是 `build` |
| Blocks: 编引导 | `boot` |
| Blocks: 运行（串口） | 在「Blocks 串口」终端执行。x64：`run --headless`。Arm64 virt：`run-virt-arm --headless`。RiscV virt：`run-virt-riscv --headless`。真板不启动 QEMU，改执行 `serial` |
| Blocks: 运行（窗口） | 同一终端、同一短名，但不加 `--headless`。没有 `DISPLAY` 时说明原因并停。真板没有窗口运行，改执行 `serial` |
| Blocks: 打开串口 | 真板：在「Blocks 串口」执行 `serial`。QEMU 目标：说明客户壳要等「运行」把 QEMU 拉起来，不另开一条 picocom |
| Blocks: 冒烟 | `smoke` |
| Blocks: 编开发包 | `bash Kernel/Tools/build-sdk.sh` |
| Blocks: 新建应用 | 问目录名，复制模板，改写 `BLOCKS_SDK`，在 IDE 里打开该目录 |
| Blocks: 编应用 | 在应用目录执行 `make`。没有开发包目录时先说明 |
| Blocks: 生成编译数据库 | `Tools/Scripts/gen-compile-commands.sh` |
| Blocks: 选择架构与板 | 快速选择，写入设置 |

状态栏显示当前目标，例如 `Blocks x64`、`Blocks arm64 rpi-3b`、`Blocks riscv milk-v-duo-s`。点击即「选择架构与板」。

架构与板的合法组合以 `env.sh` 为准：

| 架构 | 板 | 构建参数 |
| --- | --- | --- |
| x64 | （课机，无板短名） | `build` |
| arm64 | `virt` | `build arm64` 或 `build arm64 virt` |
| arm64 | `rpi-3b` | `build arm64 pi` |
| riscv | `virt` | `build riscv` |
| riscv | `milk-v-duo-s` | `build riscv duo` |

设置项：

| 键 | 含义 | 默认 |
| --- | --- | --- |
| `blocks.root` | 仓库根。空则自动向上找 | 空 |
| `blocks.architecture` | `x64` / `arm64` / `riscv` | `x64` |
| `blocks.board` | `virt` / `rpi-3b` / `milk-v-duo-s`。x64 忽略 | `virt` |
| `blocks.hotSend` | `hotsend` 可执行文件。空则用 `$HOTSEND_CONFIG` 所在仓或 `~/HotSend` 里已编好的二进制 | 空 |
| `blocks.serialPort` | 真板串口设备。空则沿用 `KSEND_PORT`，再没有就是 `/dev/ttyUSB0`。非空时导出为 `KSEND_PORT` | 空 |

推荐扩展只写 **clangd**（Open VSX 上的那份）。VSCodium 默认市场就是 Open VSX，保持不动。不捆绑微软 C/C++ 扩展。

### 7.2 第二期命令

须二次确认（对话框写清盘或串口），因为会写卡或重启板：

| 面板文字 | 行为 |
| --- | --- |
| Blocks: 刷 Pi 卡 | `ck-pi-sd`。当前板必须是 `rpi-3b` |
| Blocks: 刷 Duo 卡 | `ck-duo-sd`。当前板必须是 `milk-v-duo-s` |
| Blocks: 部署 Duo | `deploy-duo` |
| Blocks: 部署 NUC U 盘 | `deploy-nuc-usb` |
| Blocks: 热传 | 调用 HotSend。找不到二进制时打印安装位置，不在 IDE 里克隆那个仓 |

## 8. 产品壳

### 8.1 开发期启动器

系统有 `codium` 时：

```bash
codium \
  --extensionDevelopmentPath "$BLOCKS_ROOT/Tools/Ide/Extension" \
  --user-data-dir "${XDG_DATA_HOME:-$HOME/.local/share}/blocks-ide" \
  "$BLOCKS_ROOT"
```

这一阶段窗口标题仍是 VSCodium。用来把扩展做对。

### 8.2 成品

1. 开工时把当时的 VSCodium **stable / linux-x64** 版本写进 `Tools/Ide/Product/Version.txt`，压缩包放进 `Tools/Ide/Vendor/`（或 `Tools/Tarballs/` 缓存，解压到 Vendor）。
2. 扩展的 `engines.vscode` 与该主版本一致。
3. 合并进该副本的 `resources/app/product.json`，只改这些字段：

| 字段 | 值 |
| --- | --- |
| `nameShort` | `Blocks IDE` |
| `nameLong` | `Blocks IDE` |
| `applicationName` | `blocks-ide` |
| `dataFolderName` | `.blocks-ide` |
| `linuxIconName` | `blocks-ide` |
| `urlProtocol` | `blocks-ide` |
| `updateUrl` | 空。版本由我们钉死，不跟 VSCodium 每日更新 |
| `quality` | 保持上游 `stable` |

其余字段保留，包括许可证声明和 Open VSX 市场地址。扩展放进该副本的 `resources/app/extensions/blocks-ide`，随包加载。

4. 桌面项 `com.blocks.ide.desktop`，执行启动器。图标可先用纯色块，做法对齐 `Kernel/Tools/HostChat/Tools/install-desktop.sh`，不从网上下品牌图。

成品验收时，标题栏是 **Blocks IDE**，数据不写进 `~/.config/VSCodium`。

## 10. 先不做

下面这些另立柱或等地基到了再写，不塞进上面八刀：

- 把 vscode / vscodium 源码放进本仓，或每月合并上游编辑器。
- 在 Blocks Guest 桌面里做 IDE。编译器和 QEMU 都在宿主。
- 把 QEMU 画面嵌进编辑器标签页。串口已经在「Blocks 串口」终端里。
- 用 TypeScript 实现串口读写、波特率或终端仿真。真板只调用 `serial` → `picocom`。
- Windows、macOS 安装包。
- 内核调试器（GDB stub）。等内核侧有稳定接法再单独立项。
- 命名和行数的编辑器诊断。仓里已有 `Tools/Scripts/find-old-name.py`，它是改名扫描，不是保存时的检查器。
- 第二套构建系统、第二套任务 JSON 去代替 `env.sh`。
- 改 `env.sh` 的短名语义来迁就 IDE。

## 11. 许可与依赖

- 扩展源码随 Blocks 仓库。
- VSCodium 二进制不进 git。使用上游发布的 linux-x64 压缩包，保留其许可证与第三方声明。
- 宿主需已有课机那套包（`build-essential`、`python3`、`nasm`、`qemu-system-x86`、`ovmf`，见根 [`README.md`](../../README.md)）。真板串口另需 `picocom`。IDE 不静默 `apt install`。缺命令时在终端写出缺哪个。
- Node 只在**开发扩展**时需要（安装类型声明、打包 VSIX）。成品启动器不要求用户装 Node。
