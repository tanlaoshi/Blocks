# 命名规范

> 新代码认本文。一条一条往下加。  
> 旧长篇仍在 [细则备查/命名.md](细则备查/命名.md)，日常不翻。

## 1. PascalCase

每个单词首字母大写，词与词之间不加重划线，也不写成全小写或驼峰小写。

| 要 | 不要 |
| -- | ---- |
| `SerialInitialize` | `serial_init`、`serialInitialize`、`Serial_Initialize` |

## 2. 名称写全，不用简写

一个名字里的每个单词都写完整。不要为了短而砍掉字母。

`UsbHc` 里的 **Hc** 是 **Host Controller**（USB 主机控制器）的简写，不是一个单词。按本条应写成 `UsbHostController`。

| 要 | 不要 |
| -- | ---- |
| `UsbHostController` | `UsbHc` |
| `Configure` | `Cfg` |

总线和协议的正式名字保留，例如 `USB`、`PCI`。这些是名字，不是把某个单词砍短。

## 3. 拆文件后，辅助文件不重复模块名

一个文件行数太多时，拆成一个主文件和若干辅助文件，放进同一个文件夹。主文件与文件夹同名。文件夹已经表达了模块，辅助文件不再加这个前缀。

`Kernel/HAL/X64/Drivers/XHCI` 的主文件是 `Xhci.c`。其下辅助文件不写 `Xhci` 前缀。

已有目录里还在重复前缀的，慢慢改。`XHCI` 的辅助文件已经去掉前缀，主文件仍是 `Xhci.c`。和 EHCI、Wifi 重名的函数留着 `Xhci` 前缀。记在 [../项目/进展/路线图1021.md](../项目/进展/路线图1021.md)「记下」。

| 要 | 不要 |
| -- | ---- |
| `XHCI/Xhci.c` | 把主逻辑再改名，使文件夹里没有主文件 |
| `XHCI/UsbHostController.c` | `XHCI/XhciUsbHostController.c` |

## 4. 函数名不重复文件名

函数名不要再把文件名加在前面。文件已经说明这是哪一块，函数名只写它自己的动作。

一个文件里有一个主函数编排流程，其余函数是辅助。一个文件放不下，就拆成多个文件，而不是把名字加长。

`UsbHostController.c` 里不要叫 `UsbHostControllerInterruptQueue`。

| 要 | 不要 |
| -- | ---- |
| `InterruptQueue` | `UsbHostControllerInterruptQueue` |

## 5. 头文件：主文件与目录同名，辅助头不重复目录名

包含已经带目录（`Ehci/Private.h`）。同名头不再靠 `-I` 顺序区分，所以辅助头可以都叫同一个名字。

| 要 | 不要 | 是哪一种 |
| -- | ---- | -------- |
| `Serial/Serial.h` | `Serial/Private.h` | 主文件，和目录同名 |
| `Ehci/Private.h` | `Ehci/EhciPrivate.h` | 辅助头，目录已经说明是谁 |
| `Iwl/Private.h` | `Iwl/IwlPrivate.h` | 同上。`IwlPrivate.h` 是旧写法，后续改 |

`XHCI/Internal.h` 也是辅助头，后续和 `Private.h` 用同一个词。本条不改函数名，也不把主文件改成 `Private.h`。

## 6. 短函数名放进登记表

内核一次链接，全局只有一张符号表。`Write`、`Initialize` 不能各有一份全局函数。

一个模块对外一张操作表。表里的字段用短名。真正干活的函数写成 `static`，短名只在本文件。别的目录拿这张表来调用，不在头文件里再声明一排全局的 `Write`、`Initialize`。模块初始化时把表填上。

只在本文件里用的函数，直接 `static`，不必进表。

会和别的模块撞名的全局函数，不靠加前缀来躲。收到这张表里。碰到一个目录做一刀，不把整个内核一次改完。

## 7. 名词在前，动词在后

名字要顾名思义：先读到是哪一块、哪件东西，再读到它做什么。

动词不要放在名词前面。`InitializeConsole` 应写成 `ConsoleInitialize`。

层前缀放在最前面，后面仍是名词再加动词。Hal 就是这种前缀：`HalSerialInitialize`。

登记表里的字段仍用短动作名，见 §6。本条管的是要让人一眼看懂的那个名字。

| 要 | 不要 |
| -- | ---- |
| `ConsoleInitialize` | `InitializeConsole` |
| `HalSerialInitialize` | `InitializeHalSerial`、`HalInitializeSerial` |

## 8. 写完自查

每刀改完 `.c` / `.h`、报收口之前：对照本文 1～7，并确认碰过的实现文件 **≤300 行**。  
有简写或超行就当场改，不要等别人指出。行数门槛与拆分形态见路线图 [〇·代码原则](../项目/路线图.md#sec-0-code)。
