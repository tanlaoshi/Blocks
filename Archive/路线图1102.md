## ★ 决策记录：Milk-V Duo **不接屏**，作为 console-only 的代表

> **2026-11-02 定**：Duo 的定位固定为 **console-only 基线** —— 不接 SPI 屏、不接 MIPI 屏。
> 理由：① 三架构需要一台"纯净串口基线"来验证内核与驱动，不被显示需求绑架；
> ② Duo 无 USB 主机，接了屏也点不了鼠标，价值有限；③ MIPI 通路要厂商 VPSS 全家桶（2–4 周），
> 而收益只是"多一块屏"。

**连带结论**：

| 项 | 结论 |
|---|---|
| `BOARD_HAS_FRAMEBUFFER` | 保持 `0`（现状），不新增显示驱动 |
| `Gui` / 桌面 | Duo 不加载（本来就没有 FB，`Guis` 走 ConsoleOnly 表） |
| Grove 字符屏（I2C 16×2） | **可选、非目标**；如果想练 I2C 可以单独做，不属"显示"线 |
| 之前讨论的 SPI/MIPI 屏方案 | **全部归档不做**（分析留在对话与 `Docs/21` 的显示章节之外，不再排期） |

**Duo 的"能看见"= 串口。** 显示能力由 X64（GOP）和 Pi（HDMI）承担。

## 1 · 定位：GPIO 属于"底座之下"，不做成 `.mod`

按 [`Docs/18`](../Docs/18-底座之上下-稳定内核设计.md) §4.1 三问：

- 没有它还能加载第一个模块吗？→ 能（所以不是"必需"）
- 换板子要改代码吗？→ **要**（pin 表不同）→ 所以是**板级**，不是"底座之上"的模块
- 极小 + 通用 + 观测手段？→ GPIO 接口极小，但**不是所有机器都有**（x64 没有）

⇒ **结论**：GPIO 是 **HAL 平台能力**（留核，`Include/Hal/HalGpio.h` + 各板实现），
**但"给应用用"的那层（设备/服务面）归底座之上**（G6，可选）。

**为什么不做成 `.mod`**：电源键、LED、按键、复位脚都可能依赖它，属于"驱动的地基"；
把它做成模块，会让每个用 GPIO 的驱动都依赖一个模块（违反"模块之间零依赖"）。

|---|---|
| **做** | Pi：`GPEDS0/GPAREN0/GPAFEN0` + 清中断；Duo：DW GPIO `INTEN/INTTYPE_LEVEL/INT_POLARITY/INTSTATUS/PORTA_EOI`；接进设备模型 → 事件队列 |
| **判据** | 按键（或定时翻转模拟）产生**恰好一次**事件；连续 1000 次不丢不重 |
| **依赖** | 需要 G1 的契约先支持"事件回调/轮询两种取法" |

### G6 · `gpio-device` —— 设备/服务面（可选，最后）<a id="gpio-device"></a>

| 项 | 内容 |
|---|---|
| **做** | 把 GPIO 控制器注册成 `DEVICE_NODE`（`DEVICE_BUS_FIXED` + class GPIO）；应用通过对象打开、读写 |
| **判据** | 一个 app（或 shell 内建测试）点亮/熄灭 LED；拔掉该"服务"系统照常 |
| **备注** | 与模块化的接口对齐：将来 GPIO 的"用户面"可以是一个 `.mod`，底层 HAL 留核 |

## 3 · 串口/热更口径（避免抢线）

| 板 | 热更方式 | 命令 |
|---|---|---|
| Duo | 串口差量写 `boot.sd` | `deploy.sh --no-build --elf <elf> --port /dev/ttyUSB0` → 板上 `reboot` |
| Pi | `ksend` 写 `BLOCKS:Kernel.elf` + 复位 | `python3 Tools/ksend.py --port /dev/ttyUSB0 --path BLOCKS:Kernel.elf` |
| x64 | 不刷 | 只验编译 + QEMU 上 `gpio selftest` 打印"不支持" |

**规则**：一根 TTL，**换板前先确认对端在提示符**；Duo 与 Pi **禁止同时占用**。

## 5 · 工程债与注意

| 项 | 注意 |
|---|---|
| Pi `HalSerial.c` 也直接写 GPFSEL1（UART ALT5） | G2 落地后**不要**把这段也改走公共接口（UART 早期初始化早于 HAL，动了会没串口） |
| Duo `Sdhci/Power.c`、`UsbHostController/Hardware.c` 直接读写 GPIO | 先不动；G3 之后再评估是否收敛（**先能跑，再统一**） |
| 命名 | `HalGpio` 前缀；不用 `Pin` 缩写；常量 `HAL_GPIO_MODE_INPUT` 这类全写 |
| 真机优先 Pi | Pi 的 GPIO 代码已被电源键验证过，风险最低；Duo 的 pinmux 风险最高，放后 |

---

## 6 · 一句话

> **GPIO 是"驱动的地基"，留在 HAL；引脚名是"板子的方言"，做成表。**
> 先契约（G1）→ Pi（G2，风险最低）→ Duo（G3，pinmux 白名单 + WiFi 回归）→ 命名（G4）→ 中断/设备面（G5/G6）。
