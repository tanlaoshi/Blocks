## ★ 决策记录：Milk-V Duo **不接屏**，作为 console-only 的代表

> **2026-11-02 定**：Duo 的定位固定为 **console-only 基线** —— 不接 SPI 屏、不接 MIPI 屏。
> 理由：① 三架构需要一台"纯净串口基线"来验证内核与驱动，不被显示需求绑架；
> ② Duo 无 USB 主机，接了屏也点不了鼠标，价值有限；③ MIPI 通路要厂商 VPSS 全家桶（2–4 周），
> 而收益只是"多一块屏"。

**连带结论**：

| 项 | 结论 |
|---|---|
| `BOARD_HAS_FRAMEBUFFER` | 保持 `0`（现状），不新增显示驱动 |
| `Gui` / 桌面 | Duo 不加载（本来就没有 FB，`Guis` 走 ConsoleOnly 表） |
| Grove 字符屏（I2C 16×2） | **可选、非目标**；如果想练 I2C 可以单独做，不属"显示"线 |
| 之前讨论的 SPI/MIPI 屏方案 | **全部归档不做**（分析留在对话与 `Docs/21` 的显示章节之外，不再排期） |

**Duo 的"能看见"= 串口。** 显示能力由 X64（GOP）和 Pi（HDMI）承担。

## 1 · 定位：GPIO 属于"底座之下"，不做成 `.mod`

按 [`Docs/18`](../Docs/18-底座之上下-稳定内核设计.md) §4.1 三问：

- 没有它还能加载第一个模块吗？→ 能（所以不是"必需"）
- 换板子要改代码吗？→ **要**（pin 表不同）→ 所以是**板级**，不是"底座之上"的模块
- 极小 + 通用 + 观测手段？→ GPIO 接口极小，但**不是所有机器都有**（x64 没有）

⇒ **结论**：GPIO 是 **HAL 平台能力**（留核，`Include/Hal/HalGpio.h` + 各板实现），
**但"给应用用"的那层（设备/服务面）归底座之上**（G6，可选）。

**为什么不做成 `.mod`**：电源键、LED、按键、复位脚都可能依赖它，属于"驱动的地基"；
把它做成模块，会让每个用 GPIO 的驱动都依赖一个模块（违反"模块之间零依赖"）。

### G1 · `gpio-contract` —— 公共契约 + 弱实现（✅ 2026-11-01）<a id="gpio-contract"></a>

| 项 | 内容 |
|---|---|
| **做** | `Include/Hal/HalGpio.h`：`HalGpioSetMode/Write/Read/SetPull` + `HAL_GPIO_MODE_*`、`HAL_GPIO_PULL_*`；每架构一份弱实现（x64 一律返回 -1）；`Services/Shell/Commands/Gpio.c` 骨架（`gpio selftest` / `gpio list`） |

### G2 · `gpio-pi` —— Pi 后端（把电源键那段泛化）（✅ 2026-11-01）<a id="gpio-pi"></a>

| 项 | 内容 |
|---|---|
| **做** | `HAL/Arm64/Board/rpi-3b/Gpio/Gpio.c`：pin 0–53；`GPFSEL` 设功能、`GPLEV` 读、`GPSET/GPCLR` 写、`GPPUD/GPPUDCLK` 上下拉（时序照抄现有 150 nop）；把 `Hal.c` 的 GPIO3 电源键改成调用 `HalGpio*`（**行为不变**） |
| **判据** | ✅ 真机：`gpio list` → `board=rpi-3b pins=0x36`；`gpio selftest {17,4,22,27}` 全 **PASS**（输出高/低读回一致，无需外设） |
| **回归** | 短接排针 5–9 仍能关机（电源键行为不变） |
| **风险** | `GPPUD` 时序写错 → 上拉不生效（症状：输入恒 0） |

### G3 · `gpio-duo` —— Duo 后端（DW APB GPIO + pinmux 白名单）（✅ 已真机验证 2026-11-01）<a id="gpio-duo"></a>

| 项 | 内容 |
|---|---|
| **做** | `HAL/RiscV/Board/milk-v-duo-s/Gpio/Gpio.c`：`GPIOA @0x03020000`（DDR 定方向、DR 写、**EXT_PORTA `+0x50` 读回**）；pinmux：从厂商 **`cv181x_reg_fmux_gpio.h`**（Duo S=SG2000）抄白名单偏移（先 GPIOA18/19/20 = JTAG pads，FUNC=3） |
| **判据** | `gpio selftest {18,19,20}` / `GP18`… 输出高→EXT_PORTA 读回 1；`gpio list` named=3；非白名单拒绝 |
| **回归** | WiFi：`wififw write confirm` → `bringup` → `scan` 仍过 |
| **红线** | **命令里的 pin 必须在白名单内**，否则直接拒绝 —— 防止把 UART/SD 脚改掉导致失联 |
| **风险** | pinmux 表搬错 = 可能改掉串口脚 → 所以**先只做 2–3 个安全脚**，逐个验 |
| **实现者** | Cursor（`milk-v-duo-s/Gpio/Gpio.c`，未提交 WIP）；白名单 GPIOA18/19/20 = JTAG_CPU_TCK/TMS/TRST pad，pinmux 偏移 0x68/0x64/0x6c（**cv181x** 头文件，Duo S 正确）、字段偏移 0、掩码 0x7、功能值 3=XGPIOA |
| **评审备注** | ① `DuoGpioSelectAsGpio` 假设字段偏移恒为 0（当前三个脚成立；将来加脚若偏移非 0 会写错字段，应把 OFFSET/MASK 一起进白名单表）；② `HalGpioSetPull` 只支持 NONE（cv181x 另有 IOCFG 寄存器）；③ `HalGpioCount()` 返回 32 但实际可操作只有白名单 3 个，命令层范围检查会放行、操作层再拒绝 —— 行为正确但提示可以更明确 |
| **进度** | ✅ 真机：`gpio list` board=milk-v-duo-s pins=0x20 named=3；selftest 18/19/20/GP18 **PASS**；15/16 **拒绝**；WiFi bringup+scan 绿。**本刀 TG** |

### G4 · `gpio-names` —— 逻辑 pin 名 + 板图（✅ 2026-11-01）<a id="gpio-names"></a>

| 项 | 内容 |
|---|---|
| **做** | 每板一张 `BOARD_PIN` 表（名字 → 控制器/pin/默认模式/默认上下拉）：`gpio set LED 1`、`gpio get BTN`、`gpio list` 打印本板全部具名脚 |
| **判据** | ✅ 真机（Pi）：`gpio list` → `board=rpi-3b pins=0x36 named=0x2`，两行 `LED gpio=0x11 header=0x0b out` / `BTN gpio=0x1b header=0x0d in pull-up`；`gpio set LED 1`→`get LED`=1、`set LED 0`→`get`=0；`gpio selftest LED`=PASS；未知名字打 usage（**不退化到 0 号脚**）。Duo 板图等 G3。 |
| **价值** | 上层（应用/测试脚本）不用背 GPIO 编号，换板不改命令 |

### G5 · `gpio-irq` —— 边沿（硬件锁存，不依赖 CPU 中断）（Pi ✅ / Duo ❌）<a id="gpio-irq"></a>

| 项 | 内容 |
|---|---|
| **做** | 契约加 `HAL_GPIO_EDGE` + `HalGpioEnableEdgeDetect/DisableEdgeDetect/TakeEdgeEvent`；Pi 用 GPEDS + GPREN/GPFEN；Duo 用 DW APB GPIO 的 INTEN/INTMASK/INTTYPE/POLARITY/INTSTATUS/PORTA_EOI；命令 `gpio edge / edgetake / edgeselftest` |
| **判据** | `gpio edgeselftest <pin>`：输出脚自翻转 1000 次，TakeEdgeEvent 恰好收到 1000 次（无需外设） |
| **Pi 结果** | ✅ **PASS** `toggles=000003e8`（1000/1000）。修了两处：① 原用 GPAREN/GPAFEN（**异步**，低功耗唤醒用）→ 改 GPREN/GPFEN（**同步**，Linux bcm2835-gpio 的 IRQ 路径）；② 写引脚后立刻读 GPEDS 有竞态（真机症状：连翻 3 次第 3 次丢事件）→ 取事件前做 8 次 APB 回读 |
| **Duo 结果** | ❌ `edgeselftest FAILED at toggle=0 got=0`（零事件）。寄存器语义已与 Linux `gpio-dwapb.c` 对齐（INTTYPE=1 边缘、POLARITY 定极性、INTMASK=0 解除屏蔽、INTEN=1 使能），仍未触发；WiFi 回归正常（fw/bringup/scan 全过），说明没碰坏别的东西 |
| **Duo 下一步** | 怀疑点（按序）：① 输出模式下 DW 边沿检测是否不跟随 DR（需跳线：一脚输出、一脚输入）；② v2 寄存器布局（`apm,xgene-gpio-v2` 才 remap，本 SoC 用 v1，但需实测）；③ 读 `RAW_INTSTATUS(0x44)` 而非 `INTSTATUS(0x40)`；④ IOCTRL 输入使能位 |



| 项 | 内容 |
|---|---|
| **做** | Pi：`GPEDS0/GPAREN0/GPAFEN0` + 清中断；Duo：DW GPIO `INTEN/INTTYPE_LEVEL/INT_POLARITY/INTSTATUS/PORTA_EOI`；接进设备模型 → 事件队列 |
| **判据** | 按键（或定时翻转模拟）产生**恰好一次**事件；连续 1000 次不丢不重 |
| **依赖** | 需要 G1 的契约先支持"事件回调/轮询两种取法" |

## 5 · 工程债与注意

| 项 | 注意 |
|---|---|
| Pi `HalSerial.c` 也直接写 GPFSEL1（UART ALT5） | G2 落地后**不要**把这段也改走公共接口（UART 早期初始化早于 HAL，动了会没串口） |
| Duo `Sdhci/Power.c`、`UsbHostController/Hardware.c` 直接读写 GPIO | 先不动；G3 之后再评估是否收敛（**先能跑，再统一**） |
| 命名 | `HalGpio` 前缀；不用 `Pin` 缩写；常量 `HAL_GPIO_MODE_INPUT` 这类全写 |
| 真机优先 Pi | Pi 的 GPIO 代码已被电源键验证过，风险最低；Duo 的 pinmux 风险最高，放后 |

## 6 · 一句话

> **GPIO 是"驱动的地基"，留在 HAL；引脚名是"板子的方言"，做成表。**
> 先契约（G1）→ Pi（G2，风险最低）→ Duo（G3，pinmux 白名单 + WiFi 回归）→ 命名（G4）→ 中断/设备面（G5/G6）。
