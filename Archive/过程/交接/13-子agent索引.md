## 5 · 如果只想找一个 agent

**当前唯一还可能续的**：`3de10bc3`（DHCP/数据通路）。它交付了完整代码，
但留下两个"最可能卡点"的判断；我后来又试了 9 种组合，结论写在这里：

- 空口已经能看到我们**正确、明文**的 DHCP DISCOVER（`BOOTP Request length 300`）；
- 卡在"让固件用 GTK 加密广播并标 KeyID 2"；
- 厂商做法（`sta=0xFF, pairwise=0`）→ 固件用 KeyID 0（PTK）加密 → AP 丢；
- 我改成 `sta=0, pairwise=1` → 固件**不加密**（明文）→ AP 丢；
- `data after keys: decrypted=0` 一直是 0 ⇒ **怀疑 MM_KEY_ADD 被接受但没真正生效**。

**下一步（未做）**：把 44 字节 `MM_KEY_ADD` payload 全量 dump，与厂商结构体逐字段核对
（重点 `key.array` 是否真在偏移 8），确认是不是镜像结构体错位导致"装了个空密钥"。
