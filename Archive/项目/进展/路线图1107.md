## Pixel 8（shiba，Tensor G3）

调试口：**USB-Cereal**（USB-C SBU，**1.8V**，115200）。2026-11-06 曾按步骤试过，主机没有串口输出。`PR-PIXEL8-0` 从这次失败查起。

**开干现场（2026-11-06 23:42）**

| 项 | 结果 |
|---|---|
| adb / 解锁 | ✅ `shiba`；已解锁 |
| Cereal UART 枚举 | ✅ CP2102N → `/dev/ttyUSB0`（`/dev/ttyUSB1`=别的 FT232，勿用） |
| `fastboot oem uart enable` | ✅ OKAY |
| `fastboot oem uart list` | ✅ apc/aoc/gsa/cp/dbgc=115200；gsc/tpu=921600；均 enabled=1 |
| `/dev/ttyUSB0` @115200 读 | ❌ 仅 4 字节 `NUL`，**无 bootloader 字** |

**`PR-PIXEL8-0` ✅（2026-11-06 23:49）**：电压档以**能出字的那一侧**为准（当日：离开两个母口侧；≈官方图 1.8V）。`/dev/ttyUSB0` @115200 ≈256KiB。Cereal = **CP2102N**（非 FTDI；外壳/丝印可能与官方 FTDI 示意图左右相反）。**勿用** `ttyUSB1`。Pixel 须 1.8V：开关若在 3.3V，伤的是**手机** Type-C SBU（DUT）；Cereal 侧有钳位相对不易坏。

| PR | 做什么 | 验收 |
|---|---|---|
| **PR-PIXEL8-0** | 让 bootloader 自己的字从 USB-Cereal 出来 | 主机 `115200` 看到 bootloader 输出 |
| **PR-PIXEL8-1** | `fastboot boot` 拉起板包，往这条 UART 打 `blocks>` | 串口出现 `blocks>` |

### PR-PIXEL8-0（不写内核）

1. 确认 bootloader 已解锁。未解锁时先 `fastboot flashing unlock`（会清空用户数据）。
2. 在 fastboot 执行 `fastboot oem uart enable`。
3. USB-Cereal 接到手机，主机打开 `/dev/ttyUSB*`，**115200 8N1**。插头翻面再试一次（Pixel 8 口径：**LED 朝上**）。
4. 记下三件事：主机有没有枚举出串口设备、`oem uart enable` 的返回、屏幕或串口上有没有 bootloader 自己的字。
5. 没有 bootloader 的字就停。不打 `boot.img`，不开 `PR-PIXEL8-1`。

### PR-PIXEL8-1（板包 `HAL/Arm64/Board/pixel-8/`）

1. 做 Linux `ARM64` 头垫片，打成 Android `boot.img`。ABL 只通过 `fastboot boot` 拉起，不写入机内分区。
2. 进来时已经在 EL1 就跳过降级。链接地址按 ABL 的内核加载址，不抄 Pi 的 `0x80000`，也不抄 virt 的 `0x40000000`。
3. 页表只恒等映射内核那一段，加上这路 UART 的寄存器页（Device）。
4. UART 基址从 shiba 设备树的 `stdout-path` 抄进 `BoardConfig.h`，不猜。
5. 轮询打出 `blocks>`。不打开 GIC，不编 LSE 原子指令（`-march=armv8-a`）。

## 小米 MIX 2（chiron，MSM8998）· 候补

控制台就是 bootloader 已经在扫的 splash：不点亮 DSI，不做板上 UART，不走 Type-C SBU。

这台机实测（2026-11-06，MIUI `V12.0.1.0.PDECNXM`，bootloader 仍锁着）：

| 项 | 值 |
|---|---|
| splash 物理地址 | **开机/aboot：`0x9D600000`**（线刷 DT）；运行中 MIUI DT `reg` 曾为 `0x9D400000` — 画 logo 认前者 |
| splash 长度 | `0x2400000` |
| 分辨率 | 1080×2160 |
| 位深 / stride | **32 / 4352**（`fb0` root 读，2026-11-07） |

| PR | 做什么 | 验收 |
|---|---|---|
| **PR-MIX2-0** | 备份用户文件，官方解锁 | `fastboot` 显示已解锁；内部存储的拷贝在主机上 |
| **PR-MIX2-1** | root 后读 `fb0` 的位深和 stride | `BoardConfig.h` 里写上这两个数 |
| **PR-MIX2-2** | `fastboot boot` 往 splash 画一行 | 开机 logo 上出现 `Blocks ready` 或整屏彩条；重启后原系统还在 |

### PR-MIX2-0（不写内核）

1. `adb pull /sdcard ~/mix2-backup/sdcard`。这是解锁会清掉的内部存储。应用私有数据没有 root 拉不走。
2. 留下与这台机一致的官方线刷包 `chiron` `V12.0.1.0.PDECNXM`，供以后刷回系统。
3. 用小米解锁工具按官方步骤解锁。会清空 userdata。
4. 不要把 edk2 的 `boot-chiron.img` 刷进 `boot` 分区。

### PR-MIX2-1（仍不启动自有内核）

1. 解锁并装上与 `V12.0.1.0.PDECNXM` 匹配的 Magisk root。
2. 读 `fb0` 的 `bits_per_pixel`、`stride`，以及 `splash_region@9d600000` 的 `reg`。
3. 三个数写进 `HAL/Arm64/Board/mix-2/BoardConfig.h`。和上表不一致就改上表，不沿用 OnePlus 的 `0x9D400000`。

### PR-MIX2-2（板包 `HAL/Arm64/Board/mix-2/`）

1. 参照 edk2-msm8998 的 BootShim，做 Linux `ARM64` 头垫片，打成 `boot-chiron.img`。只 `fastboot boot`。
2. 链接到 `0x80000000` 以上、躲开 aboot 解压缓冲的地址。具体数字对照该仓库 chiron 的 BootShim，不抄 Pi / virt。
3. 进来时已经在 EL1 就跳过降级。编译保持 `armv8-a`，不生成 LSE。
4. 页表只恒等映射内核那一段和 splash（**`0x9D400000`**，长度 `0x2400000`，见 `BoardConfig.h`）。不改 MDSS 时钟，不写 DSI。
5. 按 `PR-MIX2-1` 的位深和 stride（32 / 4352），在 logo 顶部画 `Blocks ready`。格式不对会先出彩条，彩条算找到显存，改对格式再收口。这一行就是这台机的控制台。
