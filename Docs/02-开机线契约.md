# 02 · 开机线契约：为什么「修一条、动一片」

> 读者画像：要改开机路径的人（包括未来的我）。
> 目标：**改一个模块前，能查到它和谁有约束、违反后用户看到什么、怎么验证没违反。**
>
> 来源：[`Archive/开机线Review.md`](../Archive/开机线Review.md)（只读评审，结论均带 `文件:行号`）。
> 分工：**Review 记事实**（谁依赖谁、错了会坏什么）；**本文记契约**（靠什么保证、怎么检查）；
> [`Archive/路线图1030.md`](../Archive/路线图1030.md) 记排期。

---

## 0 · 一句话诊断

**「修一条、动一片」不是模块太少，而是依赖只存在于注释里。**

`Kernel/BringUp/Modules.c:36-37` 自己写着：

```c
/* EARLY  Serial → PMM → VMM   早日志；PMM 必须紧挨在 VMM 前 */
```

「必须紧挨」这条约束，**编译期不查、运行期不查、CI 不查**。谁把 `Display` 插进 EARLY，或者把 `Cpu` 提前，
编译器不会说话，真机会静默死机（§2.3-K2-1 就是这么来的）。

**这份文档要把每一条这类约束，从「注释里的句子」变成「有检查位置的东西」。**

---

## 1 · 三类契约

| 类型 | 一句话 | 违反后的典型症状 |
|---|---|---|
| **O 顺序** | A 必须在 B 之前，因为 A 产出的东西 B 要用 | 静默跳过 / Park / 死机无日志 |
| **W 所有权** | 某个状态只能有一个写者 | 谁先调谁定义结果；后注册覆盖前者 |
| **F 失败策略** | 某模块失败时，是停、是降级、还是不管 | 同一层两种策略，调用点各写一遍 |

**判断一份代码「模块化够不够」的标准**：随便挑一条依赖，能不能在**代码里**找到检查它的地方。
找不到，就是靠人记着——那迟早会忘。

---

## 2 · 顺序契约（O）

「现在靠什么」一列的含义：

- **运行期失败**：有检查，但结果是模块失败/降级，日志信息有限；
- **静默降级**：有 fallback，问题被吞掉，只在某个角落留一行；
- **注释**：只有注释说明，代码不检查；
- **无**：连注释都没有，靠读代码推出来。

| ID | 约束 | 依据 | 现在靠什么 | 违反后用户看到 |
|---|---|---|---|---|
| **O-1** | PMM 紧邻 VMM 之前（页表页来自 PMM） | `PageTable.c:69/79` → `Walk.c:52-58` | 运行期失败（`PageAllocTable` 返 0 → Park） | 黑屏，串口停在 VMM 前 |
| **O-2** | VMM 早于 Video（背缓冲要分页、iGPU MMIO 要开分页） | `HalVideo.c:37-66`、`IgpuMmio.c:129-132` | 静默降级（`igpu mmio defer` 一行） | 桌面能起，**没有 GPU 加速/Present** |
| **O-3** | `KernelAttachEarlyVideo` 早于所有写屏模块 | `Kernel.c:94-97`、`:107` | 注释 | 早期日志全丢（`Width=0` 空转） |
| **O-4** | Cpu 早于 Driver / Smp（GDT/IDT/TSS/LAPIC/IOAPIC） | `Architecture.c:182-202` | 注释 | Driver/Smp 用到未初始化的中断设施 |
| **O-5** | Smp 早于 USB（MSI 目的核来自 `gApicIds[]`） | `Irq.c:12-14`、`SmpBoot.c:131+` | 静默降级（回退 BSP id） | 键鼠「点一下动一下」或假死 |
| **O-6** | SESSION（Scheduler/Console）早于 FS/Gui/Net | `Scheduler.c:87-98`、`Console.c:366-379` | 注释（`Modules.c:163-164` 提前 publish 兜着） | 命令表缺失、调度槽未建 |
| **O-7** | USB 早于 FileSystem（MSC claim 要 xHCI） | `FileSystem.c:353-412` | 注释 | U 盘永远挂不上，`block: no drives` |
| **O-8** | FileSystem 早于 Gui（DB/字体/主题都读盘） | `WindowManager.c:242-256` | 注释 | 桌面全豆腐块、无主题 |
| **O-9** | **IDT 早于任何可能异常的代码** | `Architecture.c:188` vs `VirtualMemory.c:327` | **无**（K2-1） | 三重故障：**静默重启/黑屏，无 `#PF CR2`** |
| **O-10** | TSS 早于 IDT；`gsti` 在 LAPIC+IOAPIC 后；`HalSyscallInitialize` 在 TSS 后 | `Architecture.c:163-190`、`Hal.c:179-188` | 注释（顺序在函数体内） | `int 0x80` 用 0 当栈；中断风暴 |
| **O-11** | Block 类 Probe 在 VMM 之后 | `Driver.c:194-196`、`Nvme Block.c:43-45` | 运行期失败 + 第二次机会 | 首次 Probe 全 -1，靠 FS 阶段补 |
| **O-12** | xHCI 早于 MSC claim；PS/2 `Order=100` 最后；HDA `Order=200` 最末 | `UsbMsc.c`、`Input.c:12-32`、`Ps2.c:100-107` | `Order` 数值 | xHCI 被 PS/2 挤掉（实际是 mux，不会） |
| **O-13** | FS 内部：认卷在 `gVolCount` 填满后；U 盘 claim 在 `MountAllVolumes` 前；`Activate` 在 `PickDefault` 后 | `MountOs.c`、`UsbMsc.c:269-300`、`FileSystem.c:61-65` | 无（靠「开机单线程」） | 默认卷指向上一卷的 FAT 缓冲 |
| **O-14** | Gui 内部：`FontFtInit` 早于 `LocaleInitialize`；`ThemeLoad` 晚于 DB+字体；`SetUiScale` 晚于 `ThemeLoad`；`BootLogoFinish` 早于 `DesktopInitialize` | `WindowManager.c:247-250`、`Config.c:96-100`、`BootLogo.c:355-379` | 注释 + 历史现场（PR-21） | 汉字停在旧 stb、鼠标卡死、Logo 压住桌面 |

> **注意 O-9 和 O-10 的区别**：O-10 那些顺序**代码里是对的**（TSS→IDT→sti），
> 但 O-9 说的是「IDT 整体太晚」——它在第 5 步，而第 3 步就开分页了。
> **单条函数内顺序对，不代表阶段顺序对。**

## 3 · 所有权契约（W）

一个状态如果有多个写者，行为就取决于「谁先跑」——而「谁先跑」又是 O 类契约管的，于是两处耦合叠在一起。

| ID | 状态 | 现在的写者 | 目标主人 | 症状 |
|---|---|---|---|---|
| **W-1** | 「DB 是否已加载」 | `DbInitialize` 的 `gReady` 闩 | `DbEnsureLoaded()` 唯一入口 | 早闩成空库 → 本次会话所有配置失效（G6-1，已修一半） |
| **W-2** | 当前块设备 | `Block.c:30-36` 的全局 `gDrive` | 注册表 + 按盘号分派 | 后注册者覆盖前者，插 U 盘后内置盘读不到（D4-1） |
| **W-3** | 显示硬件初始化 | `Video.c:45` 与 `Driver.c:203` 各调一次 | `DisplayHardwareInitializeOnce()` | 偶发闪黑一帧/撕裂（K2-4） |
| **W-4** | UI 缩放 | `ThemeLoad` 写入；`ThemeInitialize` 会重置成 100 | `ThemeLoad` 唯一写者 | 第二次 `ThemeInitialize` 把缩放打回去 |
| **W-5** | 输入轮询 | `Modules.c:178-180` 与 `Usb.c:29-41` 各写一遍门闩 | `HalInputPollOnce()` | 改一处漂一处（K2-5） |
| **W-6** | FAT 层当前卷 | `BlockSelect` 全局副作用 | `FileSystemLock` 保护 | 并发读会串卷（现在靠单线程） |
| **W-7** | 字形缓存代次 | `gCacheGen`（`TrueTypeCache.c`） | ✅ 已是单一主人 | 参考样板：**这条做对了** |
| **W-8** | Logo 阶段百分比 | `ModLogoPct` 按名字首字母猜 | 显式阶段表 | 新增 `S` 开头模块会跳档/卡档（K2-3） |

**W-7 是正面样例**：代次由 `gCacheGen` 一处递增，所有槽位带 `Gen`，命中要 `S->Gen == gCacheGen`。
它解决了「换字体后旧字形还在」——**这就是「单一主人」的价值**。

## 4 · 失败策略契约（F）

现在同一层有两种策略，且**规则藏在两个文件里**：

| 位置 | 策略 |
|---|---|
| `Kernel.c:35-40`（Shell/Gui/Worker） | 失败 → **Park** |
| `Kernel.c:50-52`（Input） | 失败 → **只打日志** |
| `Modules.c:169-172` | 打 `***** Module X Failed *****`，**返回值被丢掉** |

**目标**：策略进表，一眼可见。

```c
typedef enum { FK_FATAL, FK_DEGRADED, FK_OPTIONAL } MODULE_FAIL;

typedef struct {
    const char *Name;
    int (*Init)(void);
    MODULE_FAIL Fail;
} MODULE;
```

| 模块 | 建议策略 | 理由 |
|---|---|---|
| Serial / PhysicalMemory / VirtualMemory | `FATAL` | 没有它们后面全无意义（O-1） |
| Cpu / Scheduler | `FATAL` | 中断/调度是全局地基（O-4） |
| Driver / FileSystem / Gui | `FATAL` | 用户预期「能进桌面」 |
| USB / Smp | `DEGRADED` | 少了键鼠慢，但还能跑（O-5） |
| Network / HDA / PS2 | `OPTIONAL` | 缺了不影响开机 |
| Theme / BootLogo / 字体 | `OPTIONAL`（但要 WARN） | 缺了难看，不算坏 |

**关键改动**：`DEGRADED` / `OPTIONAL` 失败**必须留下一条带返回值的日志**。
现在 `Init()` 的 `int` 在 `Modules.c:169` 被丢掉——**这就是「静默失败」的源头**。

## 5 · 一次性闩清单（L）

| ID | 闩 | 问题 | 现状 |
|---|---|---|---|
| **L-1** | `DbInitialize` 的 `gReady` | 失败也置 1 → 之后永远早退 | 已修：只在读成功时闩（`5fbee675`） |
| **L-2** | `ThemeInitialize` 重置缩放 | 第二次调用把 scale 打回 100 | 未修 |
| **L-3** | iGPU 五连初始化 | 只有 `IgpuMmioInit` 自带幂等 | 未修（K2-4） |
| **L-4** | `FontFtInit` | 一次初始化，`LocaleInitialize` 依赖它 | 靠 O-14 保证 |
| **L-5** | `DisplayHardwareInitialize` | 双份调用 | 未修（W-3） |

**规则**：凡是一次性初始化，**函数名必须能看出它会闩**（`*Once` / `EnsureLoaded`），
否则调用者会以为可以重入。

## 6 · 怎么算「模块化够了」

不要设「重构完成」这种目标，设这个：

> **`Modules.c` 顶部注释里的每一条「必须」「紧挨」，都能在代码里找到检查它的地方。**

当前统计：

| 类别 | 条数 |
|---|---|
| 运行期失败（有检查，但信息少） | 2（O-1、O-11） |
| 静默降级（有 fallback） | 2（O-2、O-5） |
| 仅注释 | 6（O-3、O-4、O-6、O-7、O-8、O-10） |
| **完全无检查** | 4（O-9、O-12*、O-13、O-14） |

\* O-12 有 `Order` 数值，但**没有检查「谁先绑」**。

**目标**：把「仅注释」和「完全无检查」这 10 条，逐条迁到「有检查」。

## 7 · 落地方式：夹带，不搞大爆炸

开机线**是最不能大爆炸的地方**——它一挂，连日志都没有。

**做法**：每次修 bug 时，顺手把**那一条**约束从注释迁到代码。

| 刀 | 修什么 | 顺带建立的契约 |
|---|---|---|
| 1 | P0-1：IDT 提前 | O-9 从「无」→「运行期检查」（至少能打 `#PF CR2`） |
| 2 | P0-2：自 IPI 重试 | 第一次写 `Fail = FK_FATAL` + 带原因日志 |
| 3 | P1：`DbEnsureLoaded` | W-1 建立单一入口 |
| 4 | D4-1：块后端多实例 | W-2 从单例 → 注册表 |
| 5 | 余下模块补声明 | O-4/O-6/O-7/O-8 迁入声明表 |

**每刀独立可编译、独立可回退、独立可验证。**

## 8 · 反模式清单（改代码前先扫一眼）

| 反模式 | 为什么坏 | 替代 |
|---|---|---|
| 注释里写「必须紧挨」 | 编译器和人都不会看 | 声明 `Requires` |
| `Init()` 返回 `int`，调用点丢掉 | 失败无声无息 | 策略进表 + 记返回值 |
| 全局单例 + 后注册覆盖 | 谁先跑谁定义结果 | 注册表 + 显式 ID |
| 时间常量按「3GHz 估」 | 主频一变全漂 | 墙钟/实测 ticks |
| 同一语义两个解析器 | 两份实现必然漂移 | 统一入口（ROOT.CFG，F5-1） |
| `if (VM) defer` 静默跳过 | 线上看不出降级 | 降级也要 WARN |

## 10 · 不可逆步骤前的独立审查（制度）

### 10.1 为什么要有这一条

2026-10-30 两次被外部审查救回，都是**在我方已经"跑通"之后**：

| 审查发现 | 我们当时的认知 | 若不修的后果 |
|---|---|---|
| **A1**：`SdioFifoTest` 往 fn1 `0x10` 灌 1536 B 图案 | 「FIFO 写通、读通，枚举成功」 | 协议开始前把 1536 B 垃圾留在发送 FIFO，**S4 第一条固件消息可能被污染**，失败表现是"芯片不响应" |
| **P2**：字节模式路径没写 fn1 `0x07` | 直到真机出现「1536 B 块写成功、20 B 消息第 0 字节失败」才反推出来 | 字节模式 CMD53 静默失败，块模式却正常——**症状指向"门没开"，实际是"模式没开"** |

两次的共同点：**代码能跑，日志是绿的，但语义是错的。**
运行时的绿，只证明"这条路径没崩"，不证明"这条路径是对的"。

### 10.2 规则

> **进入不可逆步骤之前，必须由「没有参与实现的人或工具」读一遍相关代码，并留下书面结论。**

「不可逆」指一旦写下去就要靠断电/重刷才能回退的操作：

| 类别 | 具体 |
|---|---|
| 写芯片 | 固件下载、写 OTP/eFuse、改校准 |
| 改介质 | 分区表、`dd`、格式化、Boot 交接（EBS） |
| 改全局契约 | 模块顺序、内存布局、页表策略 |
| 一次性的 | 首次上电的新硬件路径（第一次碰某外设） |

**不适用**：纯文档、纯日志、单文件内的局部重构、有回归测试覆盖的改动。

### 10.3 谁来做

**优先级从高到低**：

1. **独立的 reviewer agent / 外部工具（如 Cursor）**：它没写过这段代码，不会替自己辩护；
2. 另一个人（同事/未来的我隔一天再看）；
3. 自己重读——**最弱**，因为会顺着当时的思路走。

关键是**"没参与实现"**。今天那份 `Archive/Duo-Sdhci-WiFi-代码Review.md` 之所以有效，
很大程度因为它不是写代码那方。

### 10.4 审什么（四问）

1. **验收判据对不对？** 现在用来判"成功"的那一行日志，真的能证明目标达成吗？
   （反例：用 `FIFO rw ok` 证明 SDIO 枚举成功。）
2. **失败会不会假绿？** 失败路径有没有把状态置成"成功"？
   （反例：`FifoTest` 失败后仍 `Ready=1`、`return 0`。）
3. **有没有副作用？** 这段代码为了自检，往真实通道里写了什么？
   （反例：往发送 FIFO 灌测试图案。）
4. **失败信息够不够定位？** 出错时能不能只凭日志判断是参数错、门控错还是硬件错？
   （反例：只打 `write failed`，不打 `cmd/arg/blksz/pst/int/err`。）

### 10.5 结论怎么写

在 `Archive/` 下建 `<主题>-代码Review.md`，必须包含：

- **结论先行**：这段代码是什么、不是什么（防止把"探针"当成"驱动"）；
- **每条带 `文件:行号`**；
- **分级**：⚠️ 会改外显行为 / 🟡 隐患 / ℹ️ 说明；
- **写对的部分**（避免下一刀误伤）；
- **建议修序** + **硬门禁**（哪条判据不许替代）。

**只读评审，不改代码。** 改代码另开刀。

### 10.6 与本文件其它节的关系

- §7 说「夹带式」把注释约束变成检查——那是**日常**；
- §10 说「不可逆前独立审查」——那是**闸门**。

日常靠夹带慢慢收紧，闸门防止某一次改动把整个体系带偏。
两者不冲突：**夹带是增量，闸门是防断崖。**
