## 2 · 构建隔离：各用各的 BUILDDIR

`build.sh` 支持 `BUILDDIR=`。**同一时刻两个人编译，必须各用各的目录**，否则产物互清 `[已发生]`。

| 线 | 建议命令 |
|---|---|
| DUO | `cd Kernel && BUILDDIR=Build/DUO ./build.sh riscv duo` |
| PI | `cd Kernel && BUILDDIR=Build/PI ./build.sh arm64 rpi-3b` |
| 公共 | `cd Kernel && BUILDDIR=Build/common ./build.sh x86_64` |

**不要用默认 `Build/`**（x64 默认目录），它会和别人的 `Build/<名字>` 混在一起看花。

## 3 · 提交边界（这是最要紧的一节）

### 3.1 只 stage 自己的路径，**永远不要** `git add -A` / `git add .`

`[已发生]` 一次 `git add -A Archive/` 把别人三份评审文档和 WIP 一起提交了；
另一次别人的 `git mv` 已被自动暂存，我的 commit 把**搬迁扫进去但接线没带**，导致 HEAD 编不过。

**正确姿势**：

```bash
git add <你自己的文件，逐个列>
git diff --cached --name-only      # ← 提交前必看：有没有不属于你的东西
git commit -F /tmp/msg.txt         # ← 长信息走文件，别用 -m（反引号/$() 会被 shell 吃掉）
```

### 3.2 新建文件必须**显式** add

`[已发生]` `GuiProbe.c` 是新建文件没 stage，而 `Commands.c` 已调用它 ⇒ **干净 checkout 链接失败**。

**规矩**：提交前扫一遍自己动过的目录里的未跟踪文件：

```bash
git status --porcelain | grep '^??'        # 有你的新文件就 add
```

### 3.3 构建产物一律不提交

`Runtime/RootFs/**`（`Kernel.elf`、`RUNTIME-OTHER.LOG`、`HELLO.ELF` 等）是 `build.sh` 的同步副作用。
**提交前把它们排除**：

```bash
git status --porcelain | grep -v '^ M Runtime/' 
```

若已经误 stage：`git restore --staged Runtime/`。

### 3.4 提交信息要能一眼看出归属

| 线 | 前缀示例 |
|---|---|
| DUO WiFi | `feat(duo-wifi): …` / `fix(duo-sdio): …` |
| DUO 工具 | `feat(duo): ksend …` |
| PI | `feat(pi-sd): …` / `fix(pi-wifi): …` |
| 公共 | `feat(wifi-crypto): …` / `feat(fs): …` |
| 文档 | `docs(…): …` |

**理由**：出问题时按前缀就能 `git log --grep` 分清是谁那条线的改动。

### 3.5 发现对方有未提交改动时

- **不要** `git checkout -- <对方文件>`、`git restore`、`git stash` 别人的东西；
- 不要因为"编译报错在别人文件里"就去改它 —— 先看 `git diff <那个文件>` 判断是不是半成品，**是就等**；
- 真需要改共享文件（§1.3），**先在提交信息里写明动机**，事后告诉对方。

## 4 · 硬件与串口隔离

| 资源 | 现状 |
|---|---|
| `/dev/ttyUSB0` | **DUO**（我这边的 ksend 会独占，`TIOCEXCL`） |
| `/dev/ttyUSB1` | NUC 的串口 |
| PI 的串口 | **由 PI 线自行确认设备名并在此登记** |

**规矩**：

1. **同一时刻只有一个持有者**。两个进程同时读同一 tty，字节会被瓜分，两边都缺字 `[已发生]`；
2. 我这边**不再常驻监控进程**；需要串口时临时打开、用完释放；
3. 若 PI 线与我在同一台机器上抢 `/dev/ttyUSB*`，**约定：DUO 只用 ttyUSB0，PI 用其余**。

## 6 · 冲突发生后的恢复流程

```bash
git status                                  # 1. 看谁的文件在脏
git diff --cached --name-only               # 2. 看暂存区里是不是混了别人的
git log --oneline -3                        # 3. 看对方最近提交了什么
git restore --staged <不属于你的>            # 4. 只撤出暂存，不丢改动
```

**永远不要**用 `git reset --hard` / `git checkout .` 处理"混了别人的改动"——那会把对方的未提交工作一起删掉。
