## 3 · X64（主线）

**已有**：UEFI → GOP → AHCI/NVMe/ATA → FAT → 调度/进程/syscall → Shell → Gui（窗口/拖拽/焦点/主题/字体）→ 应用（文件、设置、编辑、终端、商店）→ lwIP。

**最近改动**：`89092a79` 拆开 `UseVirtDesktop` 与 `IsVirtSerialConsole`（避免"有无屏"判断串味）；`c749446a` 编辑窗开窗前预热 CJK 标签。

**缺口**：
- 真网卡（非 virtio）从未在真机验过；
- 模块化设计里 X64 是主线，但 `Discover` 阶段尚未落地（见 §7 P2）。

---

## 4 · ARM64（Pi 3B）

**已有**：u-boot 启动 → PL011 串口 → HDMI（`BoardFbSetup` mailbox）→ DWC2 USB 键盘 → SDHCI 块设备 → FAT → **WiFi（BCM43430，SDIO）DHCP + ping + 托盘图标** → lwIP。

**关键事实**：
- `BOARD_HAS_BLOCK 1`（SDHCI @`0x3F300000`）、`BOARD_HAS_NET 1`（LAN9514 smsc95xx）、`BOARD_HAS_WIFI 1`；
- **SD 写只有 Sdhost 后端是真的**：`HAL/Arm64/Board/rpi-3b/Sdhci/Sdhci.c:30` 的 `SdhciWrite` 仍是
  `return 0; /* 本刀只读 */`，而 `Sdhost.c:46` 的 `SdhostWrite` 有完整实现。
  ⇒ Pi 的热更靠 Sdhost 那条路；**别把 Sdhci 当可写后端**。

**缺口**：
- `SdhciWrite` 空桩（要么补实现，要么在配置里明确禁用该后端）；
- µSD "失根盯梢"（`f4cb2703` 提到，尚未对表 X64 的完整行为）。

## 5 · RISC-V（Duo S）

**已有**：自写 FIT `boot.sd` 启动 → UART0 → SD0 块设备 → FAT → Shell → `ksend`/`deploy.sh` → WiFi（AIC8800D80）。

### 5.1 WiFi 八层（7 ✅ / 1 ❌）

| 层 | 状态 | 判据原文 |
|---|---|---|
| SDIO 枚举 | ✅ | `WiFi: sdio verdict: awake=1`、`chip id=` |
| 固件下载 | ✅ | `WiFi: fw state=done (all stages ok)`（5 段 + 101 patch） |
| 无线电配置 | ✅ | `WiFi: bringup ok (4/4)` |
| 扫描 | ✅ | `WiFi: scan summary: N APs from 3 rounds` |
| 关联 | ✅ | `join cfm ok` + `join ok (associated` |
| 四次握手 | ✅ | `msg=M1`→`tx m2`→`msg=M3`→`M3 mic ok`；**M4 被接受**（M3 不再重传） |
| 装密钥 | ✅ | `key add: ptk … cfm=0` / `key add: gtk … cfm=0` |
| **数据通路** | ❌ | `data after keys: decrypted=0` 从未变；DHCP 广播空口 **KeyID=0**（AP 回 KeyID=2） |

**卡点一句话**：`cfm=0` 之后，TX/RX 仍不按 GTK/PTK 走数据加密。
**当前在做的变量**：`dwifi-data-ptk` —— GTK 默认装法是否会冲掉 PTK 槽（`Docs/20`）。

### 5.2 硬件缺口

- `BOARD_HAS_FRAMEBUFFER 0`：**设计决定不接屏**（2026-11-02 定，作 console-only 基线；
  显示能力由 X64/Pi 承担。SPI 屏与 MIPI 屏两条方案均归档不做）；
- 无 USB 主机 → 无输入设备。
