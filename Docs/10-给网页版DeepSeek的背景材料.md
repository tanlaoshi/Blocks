# 10 · 拿去和网页版 DeepSeek 讨论用的背景材料

> **怎么用**：把本文整段贴给网页版 DeepSeek，然后直接问你想问的（例如「内核该保留什么」「模块还是用户态」）。
> **为什么需要它**：网页版读不到我的仓库，所以这里把**事实、约束、已否掉的方案**都写全，
> 避免它凭想象给建议。
> 文中标 **[事实]** 的可直接采信；标 **[未验证]** 的是推断。

---

## 1 · 这是什么项目（[事实]）

一个自己写的操作系统内核（叫 Blocks），单仓，同时支持三种架构：

- x86_64（开发主力，有完整桌面：窗口、光标、字体、设置、文件管理器）
- ARM64（树莓派 3B，命令行靶，正在开发 WiFi）
- RISC-V（Milk-V Duo S，命令行靶，WiFi 已能扫描、能关联）

**规模**（按源码行数，不含第三方）：

| 子系统 | 行数 |
|---|---:|
| `Core/`（调度/进程/内存/ELF 装载/syscall） | 9,845 |
| `HAL/X64/`（驱动 + 桌面相关） | 42,406 |
| `HAL/RiscV/`（含 Duo WiFi 6,245） | 14,874 |
| `HAL/Arm64/`（含 Pi WiFi） | 10,817 |
| `HAL/Common/`（视频、WPA2 算法、lwIP 端口） | 5,556 |
| `Services/Gui/`（窗口管理/绘制/光标/备份） | 8,260 |
| `Services/Desktop/`（图标/任务栏/开始菜单） | 5,447 |
| `Services/Look/`（字体栅格/主题） | 6,438 |
| `Services/Apps/`（设置/文件/商店 UI） | 4,889 |
| `Services/Store/` | 5,176 |
| `Services/FileSystem/` | 2,683 |
| `Library/`（FAT/Block/字体库） | 13,856 |
| `ThirdParty/lwip` | 131,718（编进内核） |

内核镜像是**单一 ELF**（x64 约 2.98 MB）。

## 2 · 已经有的系统能力（[事实]，都跑在真机）

- **用户态 + 独立地址空间**：有 `HalInstallUserMode()`、`VIRTUAL_ADDRESS_SPACE`、
  `ElfLoadFromMemory` / `ElfLoadShared` / `ElfRelocateProgram`（含重定位）；
- **系统调用表**（`Include/Abi/SyscallABI.h`，20+ 类）：
  - 线程/进程：`THREAD_CREATE/JOIN`、`PROCESS_FORK/EXEC/WAIT/KILL`
  - 内存：`MEMORY_BRK/MAP/UNMAP`
  - 文件：`FILE_OPEN/READ/WRITE/CLOSE/SEEK/STAT`、`DIR_OPEN/READ`
  - 网络：`NET_SOCKET/CONNECT/BIND/LISTEN/ACCEPT/RECV_NB`
  - 窗口：`WINDOW_CREATE/DAMAGE/POLL`
  - 时钟：`CLOCK_MS/TIME_SLEEP`
- **用户程序从盘上加载**：`exec` 时 `ProcessLoadPath()` 调 `VfsServiceReadFile()`，
  **从 FAT 分区读 ELF 再装载**；`Kernel/User/Apps/` 下已有 Hello / Cat / Snake / TaskMgr / Chat / WriteFile；
- **FAT 读写在真机上可用**（Duo 上用自检命令证明过：写 8 KB → 读回 → 逐字节比对 → 删）。

---

## 3 · 当前的真实痛点（[事实]）

1. **改内核 = 必须刷卡换 SD 卡**。开发 Duo WiFi 时，一轮验证 = 拔卡 + 插读卡器 + 刷 + 插回 + 上电 ≈ 5 分钟，**且必须人在场**；
2. 板子（Duo S）的启动方式是 u-boot 读 **`boot.sd`（FIT 镜像，内核内嵌在里面）**，
   **不是**读 BLOCKS 分区上的 `Kernel.elf`。所以「往分区里写新内核文件」目前**无效**；
3. 我做过一个工具（`ksend`）：通过串口按 4 KB 块**差量**把文件写进 FAT 分区，10 秒~5 分钟，
   已真机验证可用（含备份、回滚、校验）。**但它写的是 `Kernel.elf`，而板子不读那个文件**；
4. 想改成写 `boot.sd`，但**内核目前只能访问默认卷（BLOCKS）**，没有「按卷打开」的 API，
   访问不到 boot 分区；而且写坏 `boot.sd` 会让板子起不来。

## 4 · 用户提出的架构命题（讨论的核心）

> 「内核应该是电脑的大管家：**它该有的核心功能留在内核**；
> **经常可变动的代码放到外部**（可执行文件、库、或别的形式）。
> 而且不能只用『是不是在内核态执行』来切分——**内核自己也可以拆成多个文件，按需加载**；
> 外部加载的文件，也可以是**现在内核的一部分**。」

我把它理解为**两条正交的轴**：

| | **烧进内核镜像** | **从盘上按需加载** |
|---|---|---|
| **内核态** | 真正的核心（页表、调度、中断、syscall、ELF 装载、块设备+FAT 读、控制台） | **可加载内核模块** |
| **用户态** | （不应存在） | 用户程序 / 服务进程 |

我原来的规划只填了左上 + 右下两格，**漏了左下（内核模块）这一格**。

## 5 · 三条候选路线（希望讨论取舍）

### 路线 A：现状（全部编进内核）

- 优点：无新机制、无 ABI 设计、调试最简单；
- 缺点：改任何东西都要重刷内核镜像。

### 路线 B：**可加载内核模块**

把驱动/协议做成 `.km` 文件放在 FAT 分区，启动时或按需加载进内核态。

- 优点：**代码几乎不用重写**（仍是内核态，可直接调用现有函数）；不需要设计新系统调用；
  能解决「改 WiFi 不刷卡」；
- 缺点：**没有隔离**（模块崩 = 内核崩）；需要做「内核符号导出 + 重定位到内核地址空间 +
  模块生命周期（init/exit）」；模块 ABI 一旦定错很难改；
- 现状：[事实] 已有可重定位 ELF 装载器（用户态在用），但**没有**内核符号导出与模块加载器。

### 路线 C：把「策略」搬到用户态服务

例如把 WiFi 协议层（扫描/关联/WPA2，共 3,271 行）搬到用户进程 `wifid`，
内核只保留 SDIO 传输并新增一个「设备通道」系统调用（发一条消息 / 收一帧数据）。

- 优点：有进程隔离；已有进程/内存/文件系统调用可用；
- 缺点：要设计设备通道 ABI；协议层要与传输层拆开；调试变成「内核 + 进程」两条日志；
- [事实] 内核**目前没有**「把设备物理内存映射进用户态」和「把设备中断投递到用户态」的能力，
  所以**用户态驱动不可行**——只能让驱动留在内核，把协议搬出去。

## 6 · 已排除的方案（请不要重复建议）

| 方案 | 为什么排除 |
|---|---|
| **用户态驱动** | 缺设备内存映射与中断投递两个机制；收益（驱动热更新）远小于代价（内核最复杂部分要重写）。驱动本来不常改。 |
| **把内核改成微内核** | 同上；且微内核的 IPC 开销对 GUI 这类每帧路径不友好。目标是「减少内核变更频率」，不是「内核纯度」。 |
| **只靠 `fs`/`exec` 做一切** | ELF 装载 + FAT 读是**自举依赖**（还没有用户态时就要用），必须在内核里；但它们**不是内核的本质**。 |
| **写 `boot.sd` 来热更新内核** | 需要先有「按卷访问」能力；且写坏就起不来（需读卡器救）。风险高于收益，暂缓。 |

---

## 7 · 硬约束（任何方案都要满足）

1. **自举**：内核必须先能读盘 + 装载 ELF，才能启动任何用户态程序；
2. **三架构同源**：同一套代码要能编 x86_64 / ARM64 / RISC-V，板级差异走配置不靠 ifdef 堆叠；
3. **没有 IOMMU**（至少 RISC-V 那颗 C906 上没用到），用户态拿不到设备；
4. **调试只有串口**（RISC-V 目标板没有显示器，只有 UART）；
5. **改动必须可回滚**：每次迭代都要能退回上一个能跑的版本（历史上已经因为「坏提交」被迫回滚过多次）；
6. **代码规范**：函数 ≤60 行（上限 80）、文件 ≤300 行（上限 500）、不用魔法数。

## 8 · 想请你（网页版）帮忙判断的问题

1. **内核的最小集合**到底是什么？用「权威」而不是「功能」来定义（谁拥有硬件特权、谁必须在用户态之前存在、谁负责隔离）；
2. **模块 vs 用户态服务**，在「减少内核变更频率」这个目标下，哪个更划算？请给取舍依据，不要只给结论；
3. 内核模块的 **ABI 该怎么划**才能不重蹈「一旦定错就改不动」的覆辙？有没有业界的最小可行做法？
4. 「经常变动的代码放外部」这个原则，**边界该画在哪**？（例如 GUI 算不算？字体算不算？WiFi 协议算不算？）
5. 如果只能做一件事，**先做哪个**才能最快拿到「改代码不用重刷固件」的收益？

## 9 · 一些可能有用的事实（供参考，不改结论）

- WPA2 的算法（PBKDF2/PRF/MIC/GTK 解密/AES）已经从驱动里抽出成**公共模块**，
  放在 `HAL/Common/WifiCrypto/`，x86 与 RISC-V 都能链接；
- 已经有一个「跨平台文件系统写自检」命令（`fs selftest`），可作为「这板子能不能写卡」的判据；
- 板子（Duo S）内存 128 MB / 510 MB 可用（视型号），FAT 分区 57 GB。
