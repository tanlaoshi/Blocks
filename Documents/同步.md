# 用 GitHub 同步到另一台电脑

仓库：`git@github.com:tanlaoshi/Blocks.git`

日常跟踪远端分支 **`origin/main`**（本地分支名一般也是 `main`）。  
暗号：**TB** = fetch + 对齐另一台进度（只拉不推）；**TG** = 只 commit 不 push；**TS** = 只 push。细则见 [`项目/路线图.md`](项目/路线图.md)「〇、协作暗号」。

> **已废止**：旧文档里的 `working` 分流、`git push origin HEAD:working`。本地若还留着 `working` 分支，不要当主线；以 `origin/main` 为准。  
> GitHub 上若仍看到很旧的 `working`，忽略即可，不要把它 merge 进 `main`。

另一台电脑需要自己的 GitHub SSH 密钥，能 `ssh -T git@github.com`。

## 另一台第一次取代码

```bash
git clone git@github.com:tanlaoshi/Blocks.git
cd Blocks
# clone 默认已在 main，跟踪 origin/main
git status   # 应显示 Your branch is up to date with 'origin/main'
```

若那台机器以前按旧文档停在 `working`：

```bash
cd ~/Blocks
git fetch origin
git checkout main
git pull --ff-only origin main
```

## 以后两边怎么对齐

### 推（有提交要给另一台）

```bash
# 已 TG 提交后
git push origin main          # 或口令 TS
```

不要依赖裸 `git push` 若上游未设；首次可：

```bash
git push -u origin main
```

### 拉（口令 TB）

工作区干净时：

```bash
git fetch origin
git merge --ff-only origin/main
# 或：git pull --ff-only origin main
```

`--ff-only` 表示只能快进。失败说明本机有未推送提交，先理清再合，不要硬 merge 无关历史。

有未提交改动时：先 `git stash` / 提交，再拉；或只在干净树上 TB。

## 仓库里已经有的、不用另拷

这些跟着 `main` 一起下来，另一台不用从 U 盘补：

| 路径 | 作用 |
| ---- | ---- |
| `Boot/BootPkg/`、`Boot/EDK2/` | 引导程序和裁剪过的 EDK2 源码 |
| `Kernel/`（含 `ThirdParty/lwip/`） | 内核源码。lwIP 在 `Kernel/.gitignore` 里写了忽略，但现有源码已经强制入库，默认 `./build.sh` 能编 |
| `Runtime/Esp/X64/EFI/BOOT/BOOTX64.EFI` | 已提交的一份引导程序，可先用来启动 |
| `Runtime/RootFs/X64/Kernel.elf` | 已提交的一份内核，可先用来启动 |
| `Runtime/Fw/OVMF_VARS.fd.clean` | QEMU 变量盘的干净种子 |
| `Documents/`、各目录 README | 说明 |

`Kernel/.gitignore` 仍忽略 `ThirdParty/lwip/`。已经跟踪的文件会继续跟着提交；以后在 lwIP 目录里**新加**的文件，`git add` 看不见，要改它时用 `git add -f`。

## Tools：不在 git 里

`Tools/xpack-*/` 和 `Tools/Tarballs/` 被 `Tools/.gitignore` 排除。体积大约 2 GB，里面是 xPack 交叉编译器，并带有符号链接（直接放在 `Tools/` 下，不再套 `Extract/`）。

**只做 X64 时不用拷 Tools。** Boot 和 Kernel 的 X64 构建用的是系统自带的 `gcc`。

**要编 Arm64 或 RiscV 时才需要这些 xPack。** 本机现有两套：

- `Tools/xpack-aarch64-none-elf-gcc-13.2.1-1.1/`
- `Tools/xpack-riscv-none-elf-gcc-13.2.0-2/`

内核 Makefile 会先找 `Blocks/Tools/xpack-*`。找不到再退到 PATH 上的 `aarch64-linux-gnu-gcc` / `riscv64-linux-gnu-gcc`。

从这台机器拷到另一台时要保留符号链接和可执行位。U 盘若是 FAT32 或 exFAT，直接拖文件夹会把链接变成空文件或普通文件，交叉 gcc 会坏。用 tar（默认保存符号链接）：

```bash
# 这台机器（只打包 xpack 目录）
tar -C ~/Blocks/Tools -cf /media/$USER/你的U盘/Tools-xpack.tar \
  xpack-aarch64-none-elf-gcc-13.2.1-1.1 \
  xpack-riscv-none-elf-gcc-13.2.0-2

# 另一台，仓库已经 checkout 之后
mkdir -p ~/Blocks/Tools
tar -C ~/Blocks/Tools -xf /media/$USER/你的U盘/Tools-xpack.tar
```

两台都在线时，用 rsync 更合适（`-a` 保留链接、权限、时间）：

```bash
rsync -a ~/Blocks/Tools/xpack-aarch64-none-elf-gcc-13.2.1-1.1 \
  另一台用户@另一台:~/Blocks/Tools/
rsync -a ~/Blocks/Tools/xpack-riscv-none-elf-gcc-13.2.0-2 \
  另一台用户@另一台:~/Blocks/Tools/
```

`Tools/Tarballs/` 只是可选的安装包缓存，没有也可以。目标目录就是 `~/Blocks/Tools/`。

## 其他不进 git 的文件

这些都是本机生成或本机状态，clone 之后没有是正常的。按下面补，不要从陈旧分支里翻。

| 路径 | 为什么不进仓 | 另一台怎么得到 |
| ---- | ---- | ---- |
| `Boot/Build/` | 每次 `./build.sh` 重生 | `cd ~/Blocks/Boot && ./build.sh` → `Boot/Build/BOOTX64.EFI` |
| `Boot/EDK2/Conf/BuildEnv.sh`、`Conf/.cache/`、`Conf/.AutoGenIdFile.txt` | EDK2 配置脚本在本机生成 | 跑一次 `Boot/build.sh` 会写出来 |
| `Boot/EDK2/**/*.o` | BaseTools 编译残留 | 同上，首次构建会重编 |
| `Kernel/Build/` | 每次内核构建重生 | `cd ~/Blocks/Kernel && ./build.sh` → `Kernel/Build/HAL/X64/Kernel.elf`（arm64/riscv 同理换目录名） |
| `Runtime/Fw/OVMF_VARS.fd` | QEMU 运行中改写的变量盘 | 仓库里有 `.clean`。`Runtime/run.sh` 发现没有时会从 `.clean` 复制 |
| `Runtime/RootFs/Arm64/disk.img`、`Runtime/RootFs/RiscV/disk.img` | virt 盘，体积大、可再生成 | 只跑 X64 时忽略；跑 virt 时由脚本/板级说明生成 |
| `Runtime/RootFs/X64/TST.TXT`、`BIG.TXT`、`TSTDIR/`、`NestA/` 等 | 文件系统测试残留 | 不用拷，测试脚本会再写 |
| `Runtime/NvVars`、`qemu-sc.pid`、`*.log`、`*.tmp` | 一次运行留下的 | 不用拷 |
| `Kernel/Tools/HostChat/chatd` | 宿主聊天工具的编译结果 | 要用再在那台机器编 |
| `*.local`、`Config.local.txt` | 本机覆盖 | 那台机器自己写；没有就用仓库默认 |
| `*.o`、`.DS_Store` | 杂物 | 不用拷 |

X64 的引导程序和内核在 `Runtime/` 里各有一份已提交的副本，所以 clone 之后即使还没编译，盘上的 `BOOTX64.EFI` 和 `Kernel.elf` 也在。要换成刚编出来的版本：

```bash
cd ~/Blocks/Boot && ./build.sh
cd ~/Blocks/Kernel && ./build.sh
cd ~/Blocks/Runtime && ./sync.sh
```

`Runtime/sync.sh` 把 `Boot/Build/BOOTX64.EFI` 和 `Kernel/Build/HAL/X64/Kernel.elf` 抄进 `Runtime/Esp` 和 `Runtime/RootFs/X64`。它要求这两份构建产物已经存在，不会只用仓库里的旧副本。

真机刷盘（有板时）：口令 **TBN**（NUC SSD）/ **TBU**（U 盘），脚本在 `Kernel/Scripts/sync/`。

## 另一台要另装的系统包

### X64（日常桌面 / NUC）

```bash
sudo apt install build-essential python3 nasm uuid-dev qemu-system-x86 ovmf
```

`Runtime/run.sh` 读取固件 `/usr/share/OVMF/OVMF_CODE_4M.fd`（`ovmf` 包提供）。变量盘种子 `OVMF_VARS.fd.clean` 已在仓库里。

```bash
cd ~/Blocks/Runtime && ./run.sh --headless
```

串口输出在启动 QEMU 的那个终端。

### Arm64 / RiscV（QEMU virt）

```bash
sudo apt install qemu-system-arm qemu-system-misc   # aarch64 + riscv64 模拟器
# 交叉编译器：优先用 U 盘/rsync 拷来的 Tools/xpack-*（见上）
```

```bash
source ~/Blocks/env.sh
build arm64                      # → Kernel/Build/HAL/Arm64/Kernel.elf（BOARD=virt）
run-virt-arm --headless
# 树莓派板包（只验能编）：build arm64 BOARD=Raspberry/Pi3BPlus LWIP=0
```

RiscV 同理：`build riscv` + `run-virt-riscv`。

树莓派 3B+（公司 QEMU / 回家 SD）排期与拆刀见活档 [路线图1023.md](路线图1023.md#rpi-desk)；xPack 仍见上文「Tools」。
