## 0. 先答：后台只有一个 worker 吗？

**专用后台任务只有一个：`worker`（`WorkerTask`）**，钉在 **BSP CPU0**。

它按优先级泵三件事（忙则 `continue`，空则 `HalCpuHalt`）：

1. **`StoreJobStep`** — 商店装卸（窗/Shell 只 Enqueue）  
2. **`HalIwlBgPump`** — iwl Wi‑Fi 固件/后台关联切片  
3. **`LwIpDhcpStep`**（真机 NIC epoch 变化时先 `LwIpDhcpRestart`）

**不是**「全系统只有这一处在干活」。还有协作轮询（同进程多任务，不是第二套 Worker 线程池）：

| 角色 | 任务 | 泵什么 |
| ---- | ---- | ------ |
| shell | `ShellTask` | 键鼠 dequeue、Present、COM1、`LwIpService`/`HalNetPoll` |
| gui | `GuiTask` | `GuiPollMouse` / 桌面时钟 |
| input | `InputTask`（仅 **SMP≥3** → CPU2） | `HalInputPoll`（xHCI/PS2） |
| idle\* | 每核一个 | halt |
| KernelTaskDemo | `Services/Tasks/KernelTask` 演示槽 | 教学进度（非 Store） |

稳态 HID：SMP≥3 走 `InputTask`；否则 Gui/Shell 的 `YieldForPollInput`。  
USB MSC 热拔：`DesktopTickClock`（~2 Hz）→ `HalUsbMscHotPoll`。  
Store 写盘长 IO：`StoreIoBreath` → `SchedulerIoBreath`（在 worker 上下文里保鼠标）。

**产品化不做**：Store 线程池、多作业并行队列（见路线图 `PR-S-job` 非目标）。

**多 Shell / 异步命令（2026-09-27）**：每窗独立 scrollback（`RaiseWindow` 挪槽时 `ConsoleSbShiftRaise` 跟随）；`net dhcp` / Shell `store …` 先 `HoldPrompt`，完成后再 `toyos>`；其它 Shell 可照常输入。  
**开机日志**：`Scheduler: AP entered idle` 夹在 `iwl bg=*` 中间属正常——`SchedulerStart` 后 AP 与 Worker（iwl 后台）并行。

## 1. 冷启动总览（x86 课机 / QEMU split）

```
加电 → OVMF
  → ToyBoot (BOOTX64.EFI)
       串口 → GOP → 读 Kernel.elf → ExitBootServices → jmp KernelEntry
  → KernelEntry / Startup.c → BOOT_INFO → KernelMain
       → KernelModulesRun(gModulesFull | Virt*)
       → 创建 shell / gui / worker [/ input]
       → SchedulerStart
  → 串口 "ToyOS ready…"；桌面已画；Shell 窗按需打开
```

Arm64/RiscV virt：**无 OVMF**，`-kernel` 进各自 Startup → 同 `KernelMain`（模块表可能是 `gModulesVirtDesktop`）。

x86 上 QEMU 和真机都走下面这一条。启动从固件交机器开始，到 `SchedulerStart` 为止，人还没敲键。`Boot: Desktop Ready` 在窗口管理器里就打出了，后面还有网络、调度登记和命令表。运行时没有第二张初始化表，是 `gui`、`shell`、`worker`，以及三核及以上的 `input` 一直转到关机。

| 顺序 | 大模块 | 先读这个文件 | 它负责 |
| --- | --- | --- | --- |
| 1 | 交接 | `BringUp/X64/KernelHandoff.c`，然后 `BringUp/Kernel.c` 的 `KernelMain` | 固件交来的内存和分辨率收成开机信息，选全量这条线 |
| 2 | 顺序表 | `BringUp/Modules.c` 里的 `gModulesFull` | 后面每一步的名单。只认这一张表 |
| 3 | 串口 | `HAL/Initialize/Serial.c` | 让后面每一步都能打出卡在哪 |
| 4 | 内存 | `Core/PhysicalMemory/PhysicalMemory.c`，接着 `Core/VirtualMemory/VirtualMemory.c` | 先有物理页，再有页表，帧缓冲和设备寄存器才能映射 |
| 5 | 画面 | `HAL/Initialize/Video.c` | 用固件留下的帧缓冲画画、挂字体和主题。桌面不改走核显送屏 |
| 6 | 认卡 | `Core/Driver/Driver.c` | 扫出设备并登记驱动。块设备、核显、声卡在这里认到。认完再做一次核显和声卡初始化 |
| 7 | 处理器 | `HAL/Initialize/Cpu.c`，接着 `HAL/Initialize/Smp.c` | 中断、定时器、系统调用、浮点，然后拉起其它核 |
| 8 | 键鼠 | `HAL/Initialize/Usb.c` | 先 USB，再 PS/2。没有键盘也继续开机 |
| 9 | 文件 | `Services/FileSystem/FileSystem.c` | 卷和路径。U 盘扫口刚结束就调用 `InitializeUsbUart` |
| 10 | 桌面准备 | `Services/Gui/WindowManager/WindowManager.c` | 数据库、字体、语言、窗口管理器。串口上的 `Boot: Desktop Ready` 在这一步打出 |
| 11 | 网络 | `Services/Network/Network.c` | 网卡、UDP、教学 TCP。教学 TCP 留在这里 |
| 12 | 调度登记 | `Core/Scheduler/Scheduler.c` | 调度器就位，还没开始抢占 |
| 13 | 命令表 | `Services/Console/Console.c` | 把 shell 命令登记好。人还没输入 |
| 14 | 交棒 | `BringUp/Kernel.c` 的 `KernelMainCommon`，再读 `Core/Scheduler/Start.c` 的 `SchedulerStart` | 创建常驻任务并开始调度。启动到此结束 |

第一次顺着读时，这些目录先跳过。它们要等点击或敲命令才进来：`FilesUi`、`EditUi`、`SettingsUi`、`StoreUi`、`DevicesUi`、`TtyUi`。驱动种类看 `Include/Driver/DriverBoot.h` 的登记顺序，不必先钻进每一张卡。

## 2. ToyBoot（固件侧）

| 步 | 符号 / 文件 | 做什么 |
| -- | ----------- | ------ |
| 1 | `UefiMain` · `ToyBoot/Boot.c` | 最早串口；横幅 |
| 2 | `GetAndSetVideo` · `BootVideo.c` | 选 GOP 模式；清屏（Kernel 不再清） |
| 3 | `ReadKernelFile` · `BootKernel.c` | 找含 `TOYOS.ID` 的卷；`\Kernel.elf` 等 |
| 4 | `CheckAndLoadKernel` · `BootKernelLoad.c` | PT_LOAD → ~1MB；取入口 |
| 5 | ACPI / xHCI hint | RSDP、可选 xHCI MMIO |
| 6 | `JumpToKernel` | ExitBootServices；`BOOT_CONFIG*` → `KernelEntry` |

**慢点候选**：大分辨率 GOP；从慢 U 盘读 `Kernel.elf`。

## 3. Kernel 早期

| 步 | 符号 | 做什么 |
| -- | ---- | ------ |
| 1 | `KernelEntry` · `BringUp/X64/KernelEntry.S` | 切早期栈 |

### 4.1 `gModulesFull`（真机 / QEMU OVMF 桌面）

## 5. 调度起来之后

1. **idle** 每核；**worker→BSP**；**shell/gui→CPU1**（SMP>1）；**input→CPU2**（SMP≥3）。  
2. 桌面已就绪；任意键 / `shell` 开 Shell 窗。  
3. 真机插网后：worker 上 DHCP；iwl 长活在 `HalIwlBgPump`。

**稳优先于快的红线**（勿为加速拆掉）：

- Usb **先于** FS（MSC auto / NUC 键鼠）  
- 无 HID / 无 NIC / 无 WIFI.CFG → **软退 Continuable**，不挡桌面  
- Worker **不**在 Gui 里 Step（装卸卡鼠标已修）  
- 无线 **永不串口打 PSK**

## 7. 建议测量法（改之前先定量）

串口已有 `[Mod] <Name>`（BootLog Title Case）。脚本（ToyImage）：

```text
cd ../ToyImage
./Scripts/measure-boot.sh 3          # 无头；打戳日志 + CSV 摘要
# 日志默认 /tmp/toyos-boot-measure/runN.ts.log
# 锚点：t0=起 qemu；「桌面可点」QEMU 代理 = [Mod] Scheduler（Gui/DesktopInit 返回后）
```

手工等价：`./Scripts/run-split.sh 2>&1 | ts '%H:%M:%.S' | tee boot.log`，对齐 `ToyBoot` / `[Mod] *` / `ToyOS ready`。

真机：同一 U 盘连跑 3 次，记 **ready 墙钟** 与 **桌面可点**（墙纸出齐）两档（视觉，非串口代理）。

### 7.1 基线样本（PR-BOOT-fast-0 · 2026-09-28）

| 环境 | 样本 | ready（相对 t0） | 桌面可点 | 备注 |
| ---- | ---- | ---------------- | -------- | ---- |
| QEMU split · `TOY_SMP=1` · host Ubuntu | #1 | **2.608 s** | Scheduler **2.604 s** | `measure-boot.sh` |
| 同上 | #2 | **2.595 s** | **2.591 s** | |
| 同上 | #3 | **2.577 s** | **2.573 s** | |
| QEMU 模块驻留（#1） | — | — | — | Usb≈**140 ms**；Gui≈**133 ms**；FS≈**35 ms**（vvfat，非 Live USB） |
| NUC / 真机 U 盘 | — | *待手测* | *待手测* | 同棒连跑 3 次；预期 FS/Gui 远大于 QEMU |

**fast-1 后（同机 QEMU · 2026-09-28）**  
- 仅关墙纸：ready≈2.47–2.53 s，Gui≈**46–51 ms**  
- **+图标延后**：ready≈**2.45–2.48 s**，Gui≈**16 ms**；串口顺序 `Desktop Ready` → `ToyOS ready` → `Desktop Icons Loaded`  
真机收益更大（免冷启动读 `WALL.BMP` / 图标 BMP / Store 扫盘）。

**坑（已修）**：图标补齐勿放在 `GuiPoll→DesktopTickClock`。Worker `iwl` 读 FW 时 `SchedulerIoBreath` 会切到 Gui；Gui 再读盘 → FAT 重入 → `#GP@IsrCommon iretq`（`rsp=0`）。现改 **Worker 先于 iwl** 加载，Gui 只 `ConsumeNeedRefresh`。

解读：QEMU 上 **~2.1 s** 耗在 OVMF→ToyBoot 之前；进核后 Usb+Gui 是可见段。后续刀对比时 **ready 不得回退**；真机慢点以 NUC 墙钟为准。

> **盘上偏好**：已有 `THEME.CFG`/`TOYOS.DB` 若仍写 `wallpaper=1` 会覆盖代码默认；新种子与课机盘请用 `wallpaper=0`、`desktop=808080`（`prepare-rootfs` 缺省模板已对齐）。

优化验收：**ready 不回退**；`smoke-boot.sh` / `test-all` 仍绿；NUC 无键鼠仍进桌面。
