# 骨架与肉

> **写给**：已扫过目录、要建立「先骨后肉」心智的人。  
> **不是**：再扫一遍树，也不是把全仓读完。  
> **对照**：启动链见 [开机流程与加速.md](开机流程与加速.md)；稳态故事见 [`路线图新.md` · story-prs](../../路线图新.md#story-prs)；目录圆环见 [Kernel/README](../../../Kernel/README.md)。

---

## 0. 一句话

**骨架** = 加电后能调度、能泵输入、能挂一层 FS/网/屏的**最小闭环**（少文件、少分支）。  
**肉** = 挂在骨架钩子上的产品与设备：桌面/商店/驱动超市/字库/lwIP/多板……体积大、按事件才进。

读代码顺序：**先跟骨架走通一圈，再按用户故事往钩子上挂肉**；不要从 `HAL/X64/Drivers` 或 `ThirdParty/lwip` 正面硬啃。

## 1. 仓库级骨架（Blocks）

```text
固件 / Boot（旁挂 ../Boot）
  → Kernel BringUp/<Arch>/Entry · Handoff
  → KernelMain → ModulesRun（Init 表）
  → Create：Shell / Gui / Worker /（≥4 核）Input
  → SchedulerStart
  → 四环稳态（肉从这里被泵起来）
```

| 骨架件 | 路径（认这里） | 干什么 |
| --- | --- | --- |
| 交接与入口 | `Kernel/BringUp/` | 进 `KernelMain`；模块表（`MODULE_PHASE_*`）；Create 任务 |
| 调度 | `Kernel/Core/Scheduler/` | 钉核、就绪队列、exit/收尸钩 |
| 内存 | `Kernel/Core/PhysicalMemory` · `VirtualMemory` | 页与地址空间（exec 要挂） |
| 进程/ELF | `Kernel/Core/Process` · `Elf` · `Syscall` | `exec` / 用户态挂点 |
| 四环泵 | `Kernel/Services/Tasks/` | Shell / Gui / Worker / Input 谁泵什么 |
| Hal 门面 | `Kernel/Include/Hal/`；模块表胶水在 `BringUp/Initialize` | 屏/键鼠/串口/块的**抽象**；编排在 BringUp，不是整棵驱动树 |

仓库旁挂、**不算内核骨架正文**：`Boot/`、`Runtime/`（镜像与手测）、`Tools/xpack-*`（交叉链）、`Documents/`。

## 2. Kernel 圆环：哪圈是骨、哪圈是肉

与 [Kernel/README](../../../Kernel/README.md) 同心圆一致，但换成「能不能删还不妨碍理解主路径」：

| 圈 | 偏骨架 | 偏肉 |
| --- | --- | --- |
| **BringUp** | Entry / Handoff / `KernelMain` / Modules 表 | 演示槽（如 `KERNEL_TASK_DEMO`） |
| **Core** | Scheduler · PMM/VMM · Process/Elf · Syscall · 设备表钩子 | `FileSystem/Student`、调度 Student 模板 |
| **HAL** | `Hal*` API、当前板真正 Probe 到的那几条 | 未接设备、他架构板包、整棵 XHCI/网卡变体 |
| **Library** | VFS 门面、Fat **主路径**、CString/Text | 巨型字库数据、极少用的辅助 |
| **Services** | Tasks 四环、Shell 命令分发、Gui 开窗/合成**主链** | Desktop 装饰、Store、Apps UI、Net 细节 |
| **User** | CRT + 最小 hello 路径 | 各演示 App / 商店包 |
| **ThirdParty** | （无）只当肉 | 整棵 lwIP |

经验量级（不含字库二进制感）：骨架相关源大约是 **BringUp + Core 常用面 + Tasks + Gui/Shell 主链 + Hal 门面**；肉的大头在 **HAL/X64、Services 产品面、lwIP**。

## 3. 稳态骨架：四环 + 钩子

开机 Create 之后，骨架就是四条环（详见路线图 runtime-4 / gui-loop）：

```text
Input（够核时）── drain HID/XHCI
Gui ───────────── 唯一 GuiPollMouse；合成 / 栏
Shell ─────────── Present / 串口 / 键；blocks>
Worker ────────── MSC/钟采样、扫盘、Store、网后台…
```

肉挂在这些钩子上，而不是另起一套主循环：

| 钩子 | 骨架动作 | 挂上的肉（例子） |
| --- | --- | --- |
| 鼠标边沿 | `GuiPollMouse` → `GuiHandleClick` | 桌面图标、菜单、开窗、拖 |
| 开窗 | `GuiOpen*` → Defer/Fade | Settings/Files/Store/Devices/USER |
| 命令行 | Shell `exec` / `run user` | Process/Elf、stdout 契约、USER 窗 |
| 热拔 | Worker → MSC Policy | Mount、Fat、文件 App |
| 商店泵 | Worker Store* | Catalog/HTTP/装包 UI |
| 中断/驱动 | Hal 登记表 | 具体 NIC / 键鼠 / 块设备实现 |

故事柱（S1–S4）就是**按钩子挂肉的阅读顺序**，不是第二套架构。

## 4. 先骨后肉：推荐读法

1. **骨架一圈（可对照开机文档）**  
   `BringUp/Kernel.c` → `Modules.c` → `Scheduler/Start.c` → `Tasks` 文件头（四环）。
2. **稳态骨架**  
   `GuiPollMouse` / `ShellTask` / `WorkerTask` 各跟一圈空转（先不进 Desktop 细节）。
3. **按故事挂肉**（路线图 ★）  
   S1 开窗 → S2 hello/exec → S3 挂 U → S4 商店；路上修/优化进「收口后开」刀，不回头扫目录。
4. **事故再钻肉**  
   某驱动/某网卡/某板出问题，再进对应 `HAL/...` 或 lwIP 一角。

不要做的事：从 `Library/Fonts/cjk*.c`、整棵 `ThirdParty/lwip`、三架构 Board 对称阅读当「入门」。

## 5. 骨架检查清单（自测「我骨齐了吗」）

能口头答上即可，不必背文件名：

- [ ] 控制权如何从 Boot 到 `KernelMain`，模块表大概跑什么类 Init  
- [ ] 谁 Create 了哪几条任务、钉在哪颗核（含 Input 门槛）  
- [ ] Gui / Shell / Worker 稳态各泵什么；谁**不**泵鼠标  
- [ ] `exec` / 开窗如何挂上 Process 与 WaitPrompt  
- [ ] 块设备/键鼠是经 Hal 门面，还是业务直接 `#include` 某驱动私头（后者即分层被焊死）

齐了之后，再开 Desktop/Store/某驱动，都是**挂肉**。

## 6. 和「目录分层」的关系

| 说法 | 用途 |
| --- | --- |
| HAL / Core / Services / Library | **编译与依赖**硬规则（谁能 include 谁） |
| 骨架 / 肉 | **阅读与教学**顺序（先闭环再产品） |

二者正交：Services 里既有骨架（Tasks/四环）也有肉（Store 全套）；HAL 门面是骨，驱动树大多是肉。别用「在 Services 所以是肉」一刀切。
