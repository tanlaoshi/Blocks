> 操作页：[`驱动开发指南.md`](驱动开发指南.md) §4。现状表：[`../已完/驱动框架现状分析.md`](../../过程/柱归档/驱动框架现状分析.md) §6。

本文把现网已经在用的 **三种 Probe 匹配模式**写清楚，并标明哪些是推荐、哪些本柱**明确不做**。

---

## 0. 硬约束

| 项 | 结论 |
| --- | --- |
| 真 PCI 驱动应填表 | 新的 PCI 驱动抄 `E1000/NetE1000.c`：`DRIVER_MATCH` 写 VID/DID，或写 Class / Subclass / ProgIf（掩码 `0xFF`）。`Probe` 只用 `BusCtx` 上的那一个功能，不要再扫全总线 |
| 固定口与 USB 类仍可 `NULL` | `ps2-kbd`、`ata-pio`、virtio 固定窗、`usb-msc` 门面、`rtl8188eu` 仍是 `Match = 0`。它们不是认一块 PCI 功能 |
| `demo-driver` 单列 | 课堂靶，表继续匹配任意 Intel（`8086`，设备号通配），不按真实设备号 |
| 表驱动匹配 **已定型**（阶段 2） | `TOY_DRIVER.Match` 类型为 `const DRIVER_MATCH *`；`Match != NULL` 时框架按表过滤未绑定设备，命中则 `Probe(Self, Dev, …)` 并 `DeviceBindDriver`。规格 [`../已完/设备管理器驱动匹配.md`](../../过程/柱归档/设备管理器驱动匹配.md) |
| `Match` 的两种意思 | `NULL` = 驱动自扫；非 `NULL` = 表驱动 |
| 不改 API | `Probe` / `Bind` / `Remove` 三参数签名不变；`BusCtx` 对有表驱动为 `DEVICE_NODE *`，旧路径仍 `0` |
| `_template/` | 仍不编进 Kernel；模板仍 `Match = 0`，Demo 已填表 |

## 1. 现网怎么认设备

启动：`HalDriverRegister()` 只登记；`ToyDriverProbeClass(Class)` 对已注册驱动：
- `Match == NULL` → 旧路径 `Probe(Self, 0, &Private)`（驱动自扫 PCI/DTB）；
- `Match != NULL` → 遍历未绑定 `DEVICE_NODE`，`DriverMatchesDevice` 命中则 `Probe(Self, (void *)Dev, &Private)`，成功 `DeviceBindDriver`（一驱动一实例）。

返回 0 再 `Bind`。`lsdev` 只列 **Bound** 实例。

有表时，框架先 `DriverMatchesDevice`，`Probe` 只处理命中的那一个 `DEVICE_NODE`。`Match == NULL` 时仍由驱动自己找设备。

本树 **没有** DTB `compatible` 匹配实现。

## 2. 三模式

新人拷 `_template/` 后，按设备类型选一种写在 `Probe` 里即可。三种可以叠（例如先查 VMM，再扫 PCI）。

### 模式 A — 固定口 / MMIO

Probe 内直接碰约定地址；没有总线枚举。

| 代表 | 怎么认 |
| --- | --- |
| `ps2-kbd`（`InputPs2.c`） | i8042 口 `0x60`/`0x64`；还要求 VMM 已开、Input 槽空闲 |
| `ata-pio`（`BlockAta.c`） | 固定 I/O `0x1F0` |
| virt `virtio-*`（`HAL/Virtio/`） | **固定 MMIO 窗**扫描（`VirtioMmioScan`），**不是** DTB |

草稿：

```c
if (!VirtualMemoryEnabled()) return -1;
if (!Ps2InitHw()) return -1;   /* 或 Ata / VirtioMmioScan */
return 0;
```

### 模式 B — PCI 填表

表里写 class，或写 VID+DID。`Probe` 收到 `BusCtx`（`DEVICE_NODE *`）后再 map BAR。不要在 `Probe` 里扫全总线。

| 代表 | 表里写什么 |
| --- | --- |
| `e1000*` | VID `0x8086` + 已有 DID。新 PCI 驱动抄这个文件 |
| `ahci` | class `01:06:01`，BAR5 |
| `nvme` | class `01:08:02`，BAR0 |
| `xhci-hid` / `ehci` / `uhci` | USB class `0C:03`，ProgIF 分别是 `30` / `20` / `00` |
| `igpu` / `hda` | Intel `8086` + 显示类 `03`，或多媒体 `04:03` |

`virtio-net-pci` 仍 `Match = 0`，自己认 `1AF4:1000`。

草稿：

```c
/* .Match = gE1000Match；Probe 不再扫总线 */
if (!Dev || Dev->Bus != DEVICE_BUS_PCI || Dev->Bar[0] == 0) return -1;
if (!E1000Setup()) return -1;
return 0;
```

### 模式 C — 软条件

Probe **不**证明「这块硬件已可用」，只满足策略（例如必须在 VMM 后、允许登记）。真正认盘/挂 Backend 放到 Bind 之后的显式步骤。

| 代表 | 怎么认 |
| --- | --- |
| `usb-msc`（`BlockMsc.c`） | Probe：VMM 已开则 `return 0`；Bind **不**装 Block Mux；Shell `msc mount` 才 `BlockMscInstall` |
| 课堂 `demo-driver` | Probe 恒 0；Bind 永不 `ToyDriverInputAttach` |

草稿：

```c
if (!VirtualMemoryEnabled()) return -1;
return 0;   /* 上线策略另说，不要在 Probe 里死等热插拔 */
```

Demo 属于 C：为了 `lsdev` 可见，不是为了认真实硬件。

## 3. `TOY_DRIVER.Match` 表驱动（阶段 2 已实现）

```c
typedef struct TOY_DRIVER {
    const char *Name;
    TOY_DRIVER_CLASS Class;
    const DRIVER_MATCH *Match;   /* NULL = 旧行为；非 NULL = 表驱动 */
    int (*Probe)(const struct TOY_DRIVER *Self, void *BusCtx, void **OutPrivate);
    ...
} TOY_DRIVER;
```

`DRIVER_MATCH`（`Include/Driver/Driver.h`）按 `Type` 分 PCI / DTB / FIXED，表以 `DRIVER_MATCH_NONE` 结尾；`DriverMatchesDevice`（`Core/Driver/DriverMatch.c`）逐条比对：
- **PCI**：`(Vendor & VendorMask)==(entry.Vendor & VendorMask)` 且 `(Device & DeviceMask)==(entry.Device & DeviceMask)`；`Mask=0` 即通配。VID/DID 通过后，再比 `Class` / `Subclass` / `ProgIf`：对应掩码为 0 则忽略（旧表没写这三项，行为与以前相同）；掩码 `0xFF` 表示整字节都要相等，字段值可以是 0。
- **DTB**：`Compatible` 串全等；
- **FIXED**：`Bar[0]==entry.Base`。

`demo-driver` 示范（`HAL/X64/Drivers/DemoDriver.c`）：匹配任意 Intel PCI 设备（`Vendor=0x8086` 精确、`Device` 通配），枚举序首张 = QEMU 宿主桥 `0x8086:0x1237`，`Probe` 收到非空 `BusCtx`（`DEVICE_NODE *`），`Bind` 占实例槽使 `lsdev` 可见。

旧的 `Match = 0` 只留给 §0 那张名单；**不要**把随机结构体指针塞进 `Match`——必须是 `DRIVER_MATCH[]`。

---

## 4. 明确不做

- 把固定口、USB 类设备做成 PCI `Match` 项（键盘不单独匹配）  
- 全体驱动改成可加载模块  
- 一驱动多设备（一驱动一实例，另柱）
