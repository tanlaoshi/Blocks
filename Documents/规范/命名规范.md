# 命名规范

> 新代码认本文。一条一条往下加。  
> 旧长篇仍在 [细则备查/命名.md](细则备查/命名.md)，日常不翻。

## 1. PascalCase

每个单词首字母大写，词与词之间不加重划线，也不写成全小写或驼峰小写。

| 要 | 不要 |
| -- | ---- |
| `SerialInitialize` | `serial_init`、`serialInitialize`、`Serial_Initialize` |

## 2. 名称写全，不用简写

一个名字里的每个单词都写完整。不要为了短而砍掉字母。

`UsbHc` 里的 **Hc** 是 **Host Controller**（USB 主机控制器）的简写，不是一个单词。按本条应写成 `UsbHostController`。

| 要 | 不要 |
| -- | ---- |
| `UsbHostController` | `UsbHc` |
| `Configure` | `Cfg` |

总线和协议的正式名字保留，例如 `USB`、`PCI`。这些是名字，不是把某个单词砍短。

## 3. 拆文件后，辅助文件不重复模块名

一个文件行数太多时，拆成一个主文件和若干辅助文件，放进同一个文件夹。主文件与文件夹同名。文件夹已经表达了模块，辅助文件不再加这个前缀。

`Kernel/HAL/X64/Drivers/XHCI` 的主文件是 `Xhci.c`。其下辅助文件不写 `Xhci` 前缀。

已有目录里还在重复前缀的，慢慢改，不跟当前刀抢。先改 `XHCI`。记在 [../路线图新.md](../路线图新.md)「记下」。

| 要 | 不要 |
| -- | ---- |
| `XHCI/Xhci.c` | 把主逻辑再改名，使文件夹里没有主文件 |
| `XHCI/UsbHostController.c` | `XHCI/XhciUsbHostController.c` |

## 4. 函数名不重复文件名

函数名不要再把文件名加在前面。文件已经说明这是哪一块，函数名只写它自己的动作。

一个文件里有一个主函数编排流程，其余函数是辅助。一个文件放不下，就拆成多个文件，而不是把名字加长。

`UsbHostController.c` 里不要叫 `UsbHostControllerInterruptQueue`。

| 要 | 不要 |
| -- | ---- |
| `InterruptQueue` | `UsbHostControllerInterruptQueue` |
