# 如何写一个文件系统

> **产品名 Blocks**。默认后端 **FAT**（`Library/Fat/`）；学生模板 **Synthetic 内存盘**，默认不链进内核。

| 角色 | 路径 |
| --- | --- |
| 默认 FAT | `Library/Fat/`（`FatFsOps()`） |
| 学生模板 | `Core/FileSystem/Student/FileSystemRam.c`（+ `FileSystemRamCompat.c`） |
| 政策表 | `Include/Library/VirtualFileSystem.h` → `FS_OPS` |
| 卷/路径门面 | `FileSystem*` / VFS（业务勿直接调 Fat 内部） |

`make FS=ram` 时模板提供同名 `FatFsOps()` 别名顶替 FAT，挂载路径不用改。

## 你要改的函数

`FS_OPS` 里属于后端政策的是：

| 函数 | 做什么 |
| ---- | ------ |
| `Mount` | 准备卷；合成盘可忽略 `StartLba`。 |
| `ReadFile` / `WriteFile` | 按路径读写整文件。 |
| `DeleteFile` / `Mkdir` / `Rmdir` / `Rename` | 可选；不支持可返回 `FAT_ERR_ROFS` / `FAT_ERR_INVAL`。 |
| `ListDir` / `ListEntries` | 列目录；`ListEntries` 填 `FAT_DIRECTORY_ENTRY`。 |
| `FileStat` / `FileSync` | 可选；空指针时 VFS 层会返回 IO/错误。 |
| `ReadFileAt` / `WriteFileAt` | 可选；空 → `FAT_ERR_INVAL`。 |
| `Synthetic` | 1 = 无 Block（内存盘）；0 = 需要块设备。 |

卷前缀、`FileSystemResolve` / Activate、Block 挂载留在框架。

本模板是 **Synthetic 内存盘**：最多 8 个文件、每文件 256 字节；写不存在的路径会创建。

## 怎么编译和测试

```bash
cd ~/Blocks/Kernel
make runtests-fs                 # 默认契约 stub（FS=fat）
make FS=ram runtests-fs          # 断言 ram 模板
make FS=ram                      # 链进内核（勿当日常根盘）
```

默认 `./build.sh` / `build` 仍是 `FS=fat`。

`make FS=nosuch` 会报错，避免把未知目录扫进内核。

> `FS=ram` 的内核能编过，但不适合当日常启动根文件系统（没有真实磁盘 FAT）。课堂请用 Host `make runtests-fs` 评模板。
