# 如何写一个调度器

> **产品名 Blocks**（单仓 `Blocks/Kernel`）。默认政策 **round-robin**；学生模板默认不链进内核。

| 角色 | 路径 |
| --- | --- |
| 默认政策 | `Core/Scheduler/RoundRobin.c` |
| 学生模板 | `Core/Scheduler/Student/Priority.c` |
| 政策表 | `Include/Core/SchedulerOps.h` → `SCHEDULER_OPS` |
| 队列视图 | `SchedulerRunQueueView`（实现见 `Core/Scheduler/`） |

对照模板 `.c` 顶部人话头。

## 你要改的函数

`SCHEDULER_OPS` 里真正属于政策的是：

| 函数 | 做什么 |
| ---- | ------ |
| `Init` | 清自己的计数。不要初始化锁或队列。 |
| `Enqueue` | 把任务插进当前核的队列。数字越大越优先；同级保持先来先出。 |
| `PickHome` | 任务有 `Affinity` 就返回那一核，否则轮转。 |

`Remove` 和 `PickNext` 留在框架。`Enqueue` 被调用时，这一核的队列锁已经拿着，函数里不要再加锁。

队列通过 `SchedulerRunQueueView` 拿到槽位和个数。不要直接使用 `gRunQueue`、`gTasks`、`gIdleSlot`。

## 怎么编译和测试

在仓库根先 `source ~/Blocks/env.sh`（可选），再进入 Kernel：

```bash
cd ~/Blocks/Kernel
make runtests                 # 或：make scheduler
# 先后会用当前 SCHEDULER= 政策跑 Host 断言；默认真测 round-robin
make SCHEDULER=priority runtests   # 断言学生模板
make SCHEDULER=priority            # 把模板链进内核（再 ./build.sh 或 build）
```

默认 `./build.sh` / `build` 仍是 `SCHEDULER=round-robin`。

`make SCHEDULER=nosuch` 会报错，避免把未知目录扫进内核。
